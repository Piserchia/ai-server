# Meta Llama — research (as of 2026-09-24)

> Scope note: the "Llama" brand is now Meta's legacy open-weight line. Since April 2026 Meta's frontier work ships as the proprietary **Muse Spark** family from Meta Superintelligence Labs (MSL), and Meta's first-party **Llama API** was shut down on 2026-07-06. This document therefore covers both: Llama (open weights, third-party hosted or local) and Muse (Meta's current API/CLI/consumer surface), because any "integrate Meta" decision today is really a Muse decision with Llama as the free/local fallback.

## 3. Headless / server automation fit

**Two viable non-interactive paths; one grey path.**

1. **Meta Model API (API key).** Pure HTTP, OpenAI-SDK compatible, SSE streaming, structured output, tool calls, background/async responses, `x-ratelimit-remaining-*` headers on every response [32][35]. Auth is a static bearer key generated in the dashboard — no OAuth device flow needed [34]. Sandboxing is your problem (it is a plain LLM API). Session resume: Responses API keeps server-side state per response id (reasoning replay); no cross-day "session" object documented.
2. **Muse Code headless (`muse exec`).** Non-interactive by design "for CI/scripts"; `--json` emits JSONL on stdout; **the schema is public** even though the headless doc page is login-walled: it is the Muse Session Protocol (MSP) v1, published as `schema/msp/msp.d.ts`, `schema/msp/stable/msp.schema.json` (+ `manifest.json`, `schemaVersion: 1`, sha256-fingerprinted, `experimental: false`) and 50 golden NDJSON transcripts in the SDK repo [39][82][83][84]. Wire format = JSON-RPC 2.0, one object per line, four frame shapes (Request `{id, jsonrpc, method, params?, trace?}`, SuccessResponse, ErrorResponse, Notification `{jsonrpc, method, params?, emittedAtMs?}`); ids `sessionId`/`turnId` (UUID), `commandId` (UUIDv7), opaque `viewCursor`. Server→client notifications the runner should fold: `turn/started`, `turn/updated`, `item/started`, `item/updated`, `item/delta`, `item/completed`, `stream/delta`, `usage/updated`, `approval/request|requested|updated|resolved`, `userInput/request|answer`, `session/branchChanged|approvalModeChanged|reasoningEffortChanged`. `ItemKind` = `userMessage | agentMessage | reasoning | toolCall | userShell | subagent | workflow | reminderChild | compaction`; item status = `inProgress | completed | failed | cancelled | rejected | timedOut`. Usage fields: `promptTokens`, `outputTokens`, `totalTokens`, `usedTokens`, `windowTokens?`, and `usedPercent` (annotated "subscription" in the .d.ts) plus a `ModelCost {input, output, cached, currency}` decimal block [82][84]. Client→server methods include `initialize`, `session/start|resume|read|list|fork|compact|setApprovalMode|setReasoningEffort`, `turn/start|steer`, `approval/decide|listPending`, `goal/set|edit|pause|resume|clear`, `model/list` [84]. Exit codes 0 (turn completed) / 1 (failure, cancel, `--max-model-steps` hit) / 2 (usage error) / 130 / 143 — "how execution concluded, not whether results are correct" [76]. The transcripts README notes the protocol "evolves additively" with envelope validation tightening as coverage grows, so pin the SDK schema hash alongside the CLI version [83]. Remaining probe: confirm on an installed build that `muse exec --json` stdout is byte-for-byte the MSP notification stream (the transcripts describe the stdio host protocol; the headless page that would state the equivalence is login-walled) [81][83]. `--disable-approval` / `--approval-mode` for unattended runs; OS sandbox with network modes [28][76]. Auth: browser sign-in with a Meta Model API account (plans apply "only through the Muse Code CLI while signed in with your Meta Model API account") **or** `META_API_KEY` env var "for non-interactive environments" (note: docs use `META_API_KEY` for the CLI and `MODEL_API_KEY` for the API — verify which your build reads) [28]. Programmatic control via the TypeScript SDK over the stdio Muse Session Protocol (fully local, no server) [39].
3. **Subscription-in-headless (grey).** Muse Code plans "work only through the Muse Code CLI while signed in"; "additional API keys … use pay-as-you-go regardless of subscription status" [40]. So a signed-in `muse exec` on the Mac Mini *appears* to draw from the plan, but the docs never say headless/CI use is permitted or metered the same way, and plans meter *requests* per 5 h, not tokens [21][40]. Two new public hints, neither conclusive: the MSP schema carries a `usedPercent` usage field annotated "subscription" (so plan-metered sessions do surface quota over the same protocol `exec` speaks), and the 1.2.1 changelog says `/usage` "displays costs explicitly in USD" and that the auth store holds refreshable OAuth tokens picked up by `muse serve` hosts started logged-out [74][82] — i.e. nothing in the protocol *distinguishes* interactive from `exec` sessions. The subscriptions page (re-read 2026-09-24) still says only that the plan credential "is for use with Muse Code only" and that additional API keys are PAYG; it never mentions headless, CI or exec [40]. **Still a probe, not a finding**: probe = run `muse exec --json` signed-in with no `META_API_KEY`, fold `usage/updated`, and check whether `usedPercent` moves and the PAYG dashboard stays flat. The consumer Meta AI app / meta.ai has no programmatic surface, and Meta's Terms prohibit accessing its products "using automated means (without our prior permission)" [41]; the Meta AI ToS (updated 2026-05-13) states Meta may use interactions to improve AI [42]. Do not drive the consumer app.

**Rate limits and caps.** Meta Model API: Standard 3,000 RPM / 4,000,000 TPM; Contributor 100 RPM / 3,000,000 TPM; background responses 600/min; limits are per team, not per key [27]. A free rate tier of 60 RPM / 2M TPM and a one-time $20 credit are reported by eesel only (unverified as of 2026-09-24) [35]. Muse Code Everyday plan: 10–50 prompts per 5 h [40]. **Concurrency (cross-doc gap):** no per-plan *concurrent-session* limit is published for Muse Code (Everyday/High/Power are request-per-5h budgets, ×1/×5/×20) [40]; the only documented parallelism cap is intra-session: "The local active-child limit is CPU-derived and capped at 16", "A workflow can call up to 1,000 child tasks over its lifetime", wider request-array batches queue, and Ultra effort "default[s] to maximum parallel-agent capacity unless you set a limit" [74][85]. For the scheduler's fan-out this means: (i) N parallel `muse exec` processes on a plan are bounded only by the 5-h request budget until proven otherwise — probe with 2/4/8 concurrent signed-in execs and watch for a 429-class `provider-failure-turn`; (ii) on `META_API_KEY` the ceiling is the *team-wide* 3,000 RPM / 4M TPM (standard) or 100 RPM (contributor), shared with every other key on the account [27]; (iii) on a 10-core M4 the CPU-derived child cap (~≤16 per session) multiplies across parallel sessions, so cap subagents per job (`--max-model-steps`, workflow mode `off`/`explicit`) before fanning out [85]. Groq free tier: 30 RPM / 6K TPM / 14.4K RPD org-wide, and per-model caps such as `llama-3.3-70b-versatile` 1K RPD / 100K TPD (unverified as of 2026-09-24 — Groq's official rate-limits page does not render per-model rows without login; tokenmix instead gives 1,000 RPD / 6,000 TPM for both 70B and 8B and lists Llama 4 Maverick free at 15 RPM / 3,000 TPM / 500 RPD, which conflicts with Groq's production list showing only 3.1-8B and 3.3-70B) [43][44][48] — either way a 165K-token job blows a whole day's free 70B quota.

**Llama (open weights) headless.** Any host is an API key + OpenAI-compatible endpoint; locally, Ollama exposes `http://localhost:11434/v1` (OpenAI-compatible) with no auth, no caps, no terms beyond the Llama license.

## 7. Integration recipe for our server

**Recommended shape: two adapters, no new auth flows.**

- **Adapter A — Meta Model API via the OpenAI SDK (`openai` Python, already a common dep).** Auth: `MODEL_API_KEY` in the server's env file (metered, PAYG — an explicit exception to the subscription-preference; the contributor tier is the only near-free path and it trains on your data, so gate it to non-sensitive task classes). Enable ZDR on the key/team once the owner has read the terms (ZDR is price-parity with standard [27]); until then treat the standard tier as "not trained on, retention unknown". Use the Responses API for agentic runs and Chat Completions for classification. Streaming via SSE; structured output via `response_format`.
- **Adapter B — Llama open weights.** Local Ollama `llama3.1:8b` (and `llama3.2:3b`) on the Mac Mini for zero-cost classification/routing/sentiment; OpenRouter `meta-llama/llama-4-maverick` ($0.19/$0.65), `meta/muse-glimmer-30b` ($0.30/$1.10, 131K ctx) or Groq `llama-3.3-70b-versatile` ($0.59/$0.79) as metered bulk options [7][69][37]. Same OpenAI-SDK code path with a different `base_url`.
- **Adapter C (probe only) — Muse Code headless** as a coding worker, mirroring the existing Claude-Code lane: `muse exec` with `--json` gives an event stream the runner can log to the audit JSONL. Start on PAYG (`META_API_KEY`); the `--json` schema is now known (MSP v1 JSON-RPC notifications — see §3; fold `item/*`, `turn/*`, `usage/updated`, `approval/*` into the audit JSONL and validate lines against `schema/msp/stable/msp.schema.json` at the pinned hash [82][84]); probe step 0 becomes "confirm stdout == MSP notification stream on the installed build", step 1 "does a signed-in Everyday plan get drawn down by `exec` (`usedPercent` moves, PAYG flat)". Auth for the daemon: `META_API_KEY` env var beats the stored key beats the browser/device-code session; `muse auth set` stores a key locally; `muse logout` clears the store but not the env var [75].

Minimal sketch (Python 3.12):

```python
# src/runner/providers/meta_muse.py
import os
from openai import OpenAI

def meta_client(local: bool = False) -> OpenAI:
    if local:  # Ollama, no key, no caps
        return OpenAI(api_key="ollama", base_url="http://localhost:11434/v1")
    return OpenAI(api_key=os.environ["MODEL_API_KEY"], base_url="https://api.meta.ai/v1")

def review(memo: str, sensitive: bool = True) -> str:
    model = "muse-spark-1.3" if sensitive else "muse-spark-1.3-contributor"
    r = meta_client().responses.create(
        model=model,
        input=[{"role": "system", "content": "You are an adversarial reviewer. Return JSON."},
               {"role": "user", "content": memo}],
        reasoning={"effort": "high"},
        # tools=[{"type": "web_search"}],   # +$2.50/1K queries; enable only for research jobs
    )
    return r.output_text

def classify(text: str) -> str:            # free, local, fast
    r = meta_client(local=True).chat.completions.create(
        model="llama3.1:8b",
        messages=[{"role": "user", "content": f"Label as bullish/bearish/neutral, one word:\n{text}"}],
        temperature=0)
    return r.choices[0].message.content.strip()
```

## 8. Verdict

1. Llama is legacy: no new open Llama since April 2025, first-party API shut 2026-07-06, and the remaining value is free ≤8B local models and cheap Maverick/Scout on third-party hosts [18][61].
2. Meta's real offer is Muse Spark 1.3 — frontier-adjacent agentic quality (AA v4.3.2 max 48 / xhigh 45 vs Fable 5.1 max 53 — the article's 61–62 is pre-rescale; LMArena top-10) at $1.25/$4.25, OpenAI/Anthropic-SDK compatible, with a Claude-Code-style CLI that reads our CLAUDE.md [10][27][28].
3. Subscription path is thin: Meta One and the new Muse agent are consumer-only (no API); Muse Code plans (Everyday / High 5× / Power 20× per the official page; $5/$15/$50 per SubscriptionInsider only) are the only developer subscription, their headless/CI standing is undocumented, and no concurrent-session limit is published — though the public MSP schema (`usedPercent` "subscription") shows plan usage is at least observable from `exec` [3][40][66][82].
4. Trust and data terms are the drag: benchmark controversies, partner-only `max`, a contributor tier that trains on your prompts, standard-tier retention/residency terms behind a login wall (training use is publicly denied and a price-parity ZDR option is confirmed on the pricing page, but how to enable it is not public), and a consumer ToS that forbids financial-advice use [11][27][42][62].
5. Recommend: add Meta as a *secondary* metered adapter (review/adversarial/research) plus free local Llama 8B for routing; do not make it primary for coding or chat.

Fit scores (1–10, doc-local anchors as originally written): research **7**, coding/agentic **6**, cost efficiency **8** (standard) / **9** (contributor, with data caveat) / **10** (local Llama 8B), automation friendliness **7**, trading research **6**. **Calibrated cross-provider scores** (anchor: 10 = best lane in the 17-doc set) are in the §7 dimension table: research 6 / coding 5 / cost 8 / automation 6 / trading 5 for the standard API lane — lower because the v4.3.2 rescale puts Muse Spark 1.3 at 45–48 vs Fable 5.1's 53 and because the lane has no usage endpoint, no OTEL and no status page.
