**Release cadence & positioning (one paragraph).** Finance AI in 2026 split into three layers. (a) Consumer research UIs — Perplexity Finance, Google Finance/Deep Search, ChatGPT and Perplexity Plaid dashboards — where the LLM vendors bought or partnered for data and ship monthly. (b) Enterprise "connector" bundles — Anthropic's FactSet/S&P/LSEG/Moody's MCP connectors and Excel add-in, sold via sales, benchmarked on Vals AI Finance Agent (Opus 4.6: 60.7%) [14]. (c) A commodity layer of open MCP servers over broker/data APIs (Alpaca, Massive, EDGAR, yfinance) that any agent runtime can mount; this is the layer a self-hosted server actually uses. Alongside it, 2025-26 produced the first population-scale evidence on LLM traders (Alpha Arena, DX Terminal fleets, RetailAgent) and it is uniformly negative on *directional edge* while cautiously positive on *research-assistant* uses (nowcasting, factor proposing with a frozen statistical referee) [48][51][53][54].

- **Concurrency per lane on subscription auth (parallel headless sessions) — the scheduler's fan-out input.** Known numbers (from the sibling docs): Ollama Cloud 1/3/10 concurrent by tier; Kimi 1–4 tasks; MiniMax "3–4 agents"; Z.ai "1–2 projects". For the four lanes this server would actually fan out on, **no vendor publishes a session-concurrency cap**, and this pass re-checked: Claude Pro/Max support pages speak only of "your plan's five-hour session limit" and a weekly limit shared across Claude, Claude Code and IDEs, and say nothing about parallel instances [19][112]; the Agent SDK hosting guide bounds concurrency by host RAM ("agents per host = (host RAM − overhead) / per-session RAM ceiling", 1 GiB per agent as a floor) and warns that "large parallel-subagent fanouts can hit rate limits — break work into smaller batches" [104]; Codex publishes per-5-hour *message* ranges (Plus 350–3,000 Luna msgs; Pro 5x 1,750–14,000; Pro 20x 7,000–56,000) and "weekly limits may also apply", with no concurrency statement [22]; Gemini/Antigravity and Copilot: none found (Antigravity's `/usage` shows quotas only in the TUI [78]). Working assumption for the design: subscription lanes are **token-window-limited, not slot-limited** — N parallel sessions drain the same 5-h window N times faster and the only hard slot cap is host RAM (§ host budget below) — so the scheduler should size fan-out from the *window* (jobs × tokens/job vs the inferred 5-h allowance), keep ≤ 3 concurrent Claude subprocesses on the 16 GB host, and treat a 429 as "window exhausted, back off to the reset time" rather than "too many slots". Verify empirically: run 1, 2, 4 parallel `claude -p` jobs of a fixed prompt and record the `/usage` bar delta and any `rate_limit` events — that measurement is missing from every doc in this folder.

- **Progress-visibility sink (collector/dashboard side).** The emitters are enumerated above; the missing half is what receives them on a 16 GB Mac beside Postgres/Redis. Options, evaluated: (a) **Langfuse self-hosted** — needs Postgres + ClickHouse + Redis + MinIO + worker and "at least 4 cores and 16 GiB of memory" [107]: **rejected**, it is the whole machine. (b) **OTLP collector → Prometheus → Grafana** — three daemons; the vendor docs fetched here give no RAM figures for them (unmeasured; typical idle footprints are a few hundred MB combined, but treat that as an estimate to verify with `ps -o rss`), Claude Code and Codex both speak OTLP natively [83][104], and Prometheus can scrape Claude Code's built-in `:9464/metrics` exporter with no collector at all [83]: **viable, second choice**. (c) **No new daemon: the server's own Postgres as the sink** — Claude Code's OTLP `http/json` metrics and events can be received by a ~50-line FastAPI route on the existing gateway (`OTEL_EXPORTER_OTLP_PROTOCOL=http/json`, endpoint = the gateway), Codex OTEL likewise, and every API lane's per-response `usage` block is already in the job runner's hands: **first choice**, because the existing web dashboard already reads Postgres and `volumes/audit_log`. Common cross-lane event schema (one row per model call): `ts, job_id, lane, auth_mode(sub|api), model, effort, input_tokens, cache_read, cache_write, output_tokens, latency_ms, ttft_ms, http_status, rate_limit_hit(bool), cost_usd_list(list-price, null on sub), window_5h_id, window_week_id`. Remaining-budget inference: per subscription lane keep `allowance_5h_est` (owner-entered until measured), decrement by a *list-price-weighted* token sum (cache reads count "less" per Anthropic [112]; weight unknown → start at the API cache multiplier 0.1), reset on the window boundary observed from the first 429/`rate_limit` event; show `est_remaining_%` and `next_reset` on the dashboard and refuse to launch a job whose p90 token estimate exceeds the remainder. Codex is the exception where the number can be *read* (`rateLimits` RPC) instead of inferred — use it to calibrate the inference for the other lanes.

- **Prompt-injection / sandbox posture per lane for untrusted input (Telegram text, fetched pages, MCP tool results) — ranked.** The server ingests all three. Documented controls: **Claude Code / Agent SDK** — web fetch runs in an isolated context window, `curl`/`wget` are never auto-approved, command-injection detection and fail-closed matching in Manual mode, sandboxed Bash with filesystem + network isolation, Keychain credential storage; but "trust verification is disabled when running non-interactively with the `-p` flag" and the docs' own advice is "avoid piping untrusted content directly to Claude" and to use VMs for external web services [109]. **Codex** — Seatbelt sandbox on macOS with network off by default and approval policies (per chatgpt-openai.md; the sandbox page 404'd in this pass). **Hermes** — has an injection scan on tool results (per hermes doc). **Grok CLI** — sandbox network isolation is a no-op on macOS (per grok-xai.md). **Perplexity MCP** — tools auto-run with no approval step (per perplexity.md). **opencode** — bypasses permission prompts (per opencode doc). Ranking for untrusted-input jobs (best → worst): Claude Agent SDK with `disallowed_tools=["Bash","WebFetch","WebSearch"]` + read-only MCP allowlist (the §7 sketch) ≈ Codex in Seatbelt with network off > Hermes (scan, but scan ≠ isolation) > Gemini/Antigravity (no documented injection control found) > Grok CLI on macOS > Perplexity MCP / opencode (no gate at all). Server rule: Telegram text and fetched pages reach a model only inside a job whose tool surface is read-only by *absence of tools*, never by prompt; MCP tool results from the finance servers are trusted only for the fields the schema defines (numbers, URLs), and any free-text field (news bodies, transcripts) is treated as untrusted input to the next model call.

- **Host resource budget for always-on daemons (16 GB M4; measured `hw.memsize` = 17.18 GB).** Measured on the box during this pass (`ps -o rss`): three resident `claude` processes at 441 / 200 / 148 MB, Postgres backends ≈ 140 MB each, and — the biggest single consumer — a Devin/Windsurf language server at ≈ 1.6 GB, i.e. developer tooling, not the server. Documented budgets: Agent SDK "1 GiB RAM, 5 GiB disk and 1 CPU per agent is a reasonable starting point… a floor, not the ceiling", memory grows with session length [104]; Ollama keeps a model resident 5 min after use by default (`OLLAMA_KEEP_ALIVE`), `OLLAMA_NUM_PARALLEL` defaults to 1 and "required RAM will scale by `OLLAMA_NUM_PARALLEL` × `OLLAMA_CONTEXT_LENGTH`" [108], so a resident 7–8B model is ≈ 5–6 GB and must not coexist with a 3-agent fan-out; Langfuse ≥ 16 GiB [107] (rejected above). Undocumented (no vendor figure; measure before adopting): LiteLLM proxy, OTEL collector, Prometheus, Grafana, Hermes/OpenClaw gateway (their docs give no RAM number, per the sibling docs), Node-based CLIs (Codex, Gemini, Antigravity), Copilot session state. Budget that fits: OS + Postgres + Redis + gateway ≈ 3 GB; 3 concurrent Claude/Codex subprocesses ≈ 3 GB; headroom for one metered-lane HTTP client and the Telegram bot ≈ 1 GB; **no Ollama model resident during job windows** (schedule local-model tasks into their own window or drop `OLLAMA_KEEP_ALIVE` to 0); no Langfuse; no LiteLLM unless a second gateway is truly needed (the server already is one). Anything else needs an `rss` measurement appended here before it becomes a launchd job.

- **Reviewer independence (is a cross-vendor second opinion actually uncorrelated?).** Every doc in the folder assumes "different training lineage → uncorrelated errors". Evidence against, for specific lanes: Anthropic's 2026-02-23 disclosure alleges DeepSeek (150k+ exchanges targeting reasoning/grading), Moonshot/Kimi (3.4M+ exchanges: agentic reasoning, tool use, coding, vision) and MiniMax (13M+ exchanges: agentic coding and tool orchestration) distilled Claude through ~24,000 fraudulent accounts [106]; the kimi/minimax/deepseek/qwen sibling docs record the same allegations, and chatgpt-openai.md records a GPT-5.5 prefill-overlap experiment. Reading: a Kimi/MiniMax/DeepSeek review of a Claude-written memo is *partially the same model reviewing itself* on exactly the agentic/tool-use behaviours this server cares about; it still catches arithmetic and citation errors (independent by construction — the reviewer has the tool outputs) but should not be credited as an independent judge of *reasoning* quality. Independence ranking for the adversarial-review slot (most → least independent of Claude): Gemini (Google, no allegation found) > GPT-6 family (one documented overlap experiment, not a distillation claim) > Grok > GLM/Z.ai (no allegation found, but no evidence either) > Qwen > DeepSeek / Kimi / MiniMax (documented). Consequence for the router: the *first* adversarial reviewer must come from the top of that list (Gemini paid Flash or GPT-6 Luna/Sol), and the distilled lanes are used only as a *third* vote or for mechanical checks (numbers, links, look-ahead dates).

- **Cost-of-ownership from tool churn (release cadence / breaking-change rate per lane).** Not in dollars but in patch-jobs per month: Claude Code — near-daily releases; already flipped `--bare` semantics and `-p` defaults on this doc's own recipe (§7 gotcha 5a) and moved `/usage` totals across `/clear` at v2.1.211 [76][84]; churn **high, documented**. - **Market data — local stdio.** The Alpaca, EDGAR, yfinance and local Massive servers run as subprocesses (stdio) under launchd with env-var keys; the Alpaca and EDGAR servers warn their HTTP modes carry no auth [1][10]. - **Market data — hosted/remote MCP (new pattern, Sep 2026).** Three of the data/broker vendors now host the MCP server themselves: Massive `https://mcp.massive.com/` (browser OAuth, no key, free Basic account suffices; 2026-09-15) [65], Perplexity `https://api.perplexity.ai/mcp` (OAuth or API-key bearer) [66], Tradier `https://mcp.tradier.com/mcp` (API token + `PAPER_TRADING` header) [64]. In the Agent SDK these are `{"type": "http", "url": ..., "headers": {...}}` entries in `mcp_servers`; the SDK "doesn't open a browser or run an interactive OAuth flow" — a server that returns an authorization challenge with no stored token reports `needs-auth` and the run continues without its tools, so on a headless Mac mini the OAuth dance must be completed once out-of-band (or in the Claude Code CLI, which does cache remote-server tokens) and the resulting access token passed in `headers` [68]. Header-token servers (Tradier, Perplexity API key) are the easy case: keep the token in the launchd job's environment like any other key. OAuth-only servers (Massive remote) need a token-refresh step the job owns; until that exists, prefer the local stdio `mcp_massive` with `MASSIVE_API_KEY` [4].
- **Sandboxing / no-live-order invariant.** Keep `ALPACA_PAPER_TRADE` unset (paper default) [1]. **Tradier's remote MCP can place live equity/option/multileg orders** when given a production token with `PAPER_TRADING: false` [64] — so it is either kept off the server entirely or mounted only with a *paper* token and `PAPER_TRADING: true`, and `allowed_tools` should name the read-only tools rather than `mcp__tradier__*`. The invariant is then enforced by absence of live credentials, not by prompts.

It is API-billed, so it does not use the Max subscription; noted for completeness.

from claude_agent_sdk import query, ClaudeAgentOptions

opts = ClaudeAgentOptions(
    model="claude-sonnet-5",                       # cheap default; opus for the weekly governor
    permission_mode="acceptEdits",
    allowed_tools=["mcp__alpaca__*", "mcp__edgar__*", "mcp__massive__*", "Read", "Write"],  # auto-approves only; does NOT restrict Claude to these tools
    disallowed_tools=["WebSearch", "WebFetch", "Bash"],  # enforce the no-web-search / no-look-ahead invariant explicitly
    mcp_servers={
        "alpaca":  {"command": "uvx", "args": ["alpaca-mcp-server"],
                    "env": {"ALPACA_API_KEY": os.environ["ALPACA_KEY"],
                            "ALPACA_SECRET_KEY": os.environ["ALPACA_SECRET"]}},  # paper by default
        "edgar":   {"command": "uvx", "args": ["sec-edgar-mcp"],
                    "env": {"SEC_EDGAR_USER_AGENT": "Atlas Research (owner@example.com)"}},
        "massive": {"command": "mcp_massive", "env": {"MASSIVE_API_KEY": os.environ["MASSIVE_KEY"]}},
        # remote (hosted) MCP: header-token auth works headless; OAuth-only servers need a token
        # obtained out-of-band and passed here — the SDK never opens a browser (status "needs-auth").
        "tradier": {"type": "http", "url": "https://mcp.tradier.com/mcp",
                    "headers": {"API_KEY": os.environ["TRADIER_PAPER_TOKEN"],   # paper token only

    },
    # NOTE: allowed_tools above deliberately omits mcp__tradier__*; add only the read-only Tradier
    # tool names (quotes/history/chains/calendar) once confirmed — never the wildcard (order tools).

    # output_format takes a dict {"type": "json_schema", "schema": {...}} for schema-validated
    # final output, not the string "json" — that is the CLI's --output-format flag)
)

async def main(ticker: str):
    async for ev in query(prompt=f"Build a dated research memo for {ticker}. "
                                 "Every number must come from a tool call; cite the tool and timestamp. "
                                 "Do not size or place orders.", options=opts):
        print(json.dumps(ev.__dict__, default=str))

asyncio.run(main("SPY"))

**Gotchas.** (1) Any backtest where the agent has web search or a post-period cutoff is contaminated — freeze data snapshots per job and strip web tools in evaluation runs [46][49]. (2) Massive Basic is EOD + 5/min: cache aggressively or you will stall the job [5]. (3) Alpaca REST is 15-min delayed on the free plan; websocket is real-time but 30 symbols [2]. (4) Tokenizer: Claude 4.7+ produce ~30% more tokens for the same text, so "150k input" is bigger than it used to be [17]. (5) `ANTHROPIC_API_KEY` in the environment silently flips Claude Code to metered billing — in `-p` mode "the key is always used when present", no prompt [19][75]. (5a) `claude --bare` (the recommended mode for scripted calls, and slated to become the `-p` default) "never reads OAuth credentials or the system keychain" and requires `ANTHROPIC_API_KEY` or an `apiKeyHelper` — on a subscription-auth server that means **do not add `--bare` to scheduled `claude -p` jobs**, or they will fail auth or bill the API; get the same determinism by pointing the job at a clean working directory and passing `--mcp-config` explicitly [76]. (5b) Unattended runs should pass `--permission-prompts none` (v2.1.259+): anything that would prompt is denied instead of hanging on the host, `AskUserQuestion` is removed, and denials show up as `permission_denials` in the JSON result; the SDK equivalent is `permission_mode="dontAsk"` plus `allowed_tools` [76][68]. (5c) x402 (Massive agent endpoint) is not payable from a stock Agent SDK job: it needs a signing wallet and 402-aware HTTP client on the job side; stay on the API-key endpoints [72]. (5d) After 2026-12-06, "today's bars" from Alpaca/Massive span 9 pm–8 pm ET; pin `session` explicitly in every prompt and data fetch [73][74]. (6) yfinance is personal-use; do not make it the ledger's price source of record [12]. (7) X search bills per post fetched and does not dedupe across calls — cap `max` results and handles [27]. (8) EDGAR requires a real contact in the User-Agent [10]. (9) Log prompts, model versions and tool outputs per job — that is FINRA's template and it is what makes results auditable when a memo is wrong [59].
