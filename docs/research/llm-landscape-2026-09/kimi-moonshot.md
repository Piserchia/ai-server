## 3. Headless / server automation fit

- **Non-interactive on macOS/Linux**: `kimi -p "<prompt>" --output-format stream-json` streams JSON-lines events; `kimi login` performs the OAuth device-code flow without the TUI; `kimi doctor` validates config; `CI=1` disables theme detection; `KIMI_CODE_NO_AUTO_UPDATE=1`, `KIMI_DISABLE_TELEMETRY=1`, `KIMI_CODE_INFINITE_RETRY=1` (exponential backoff, 32 s cap), `KIMI_LOG_LEVEL` [28][29][36]. `kimi web` exposes an experimental REST (`/api/v1`, `/api/v2/sessions`, `/api/v2/mcp`) + WebSocket (`/api/v1/ws`) surface with bearer-token auth and events like `turn.started`, `assistant.delta`, `event.approval.requested`, `turn.ended` — usable for orchestration from Python, but "no guaranteed stability across releases" — the docs say to rely instead on the authenticated `GET /openapi.json` and `GET /asyncapi.json` specs "served by your version", which are generated from the same validation schemas the server enforces [31].
- **Auth modes**: (a) platform API key (`Authorization: Bearer`, from platform.kimi.ai/console/api-keys) for the raw API, Claude Code, and any harness [2][5]; (b) **Kimi Code OAuth** device-code login for Kimi Code CLI/ACP/desktop, backed by a Kimi Code subscription [29]. (c) **Kimi Code Console API key** — corrected 2026-09-24: the subscription *is* officially usable from Claude Code. The Kimi Code docs' "third-party tools / Claude Code" page says to create a key in the Kimi Code Console (kimi.com/code/console; shown once), set `ANTHROPIC_BASE_URL=https://api.kimi.ai/coding/` (the Chinese page says `api.kimi.com/coding/`), `ANTHROPIC_API_KEY=<key>`, the four `ANTHROPIC_DEFAULT_*_MODEL` slots + `CLAUDE_CODE_SUBAGENT_MODEL` to `k3` / `k3-256k` / `kimi-for-coding` (Plus/Moderato) or additionally `kimi-for-coding-highspeed` (Pro+/Allegretto+), `k3[1m]` for 1M, `CLAUDE_CODE_EFFORT_LEVEL=high`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW=262144|1048576`; it warns the key sits in plaintext in `settings.json` [100]. The membership page confirms "CLI, VS Code, Desktop, and third-party tools all count toward that quota" and "All logged-in devices and API Keys share the same quota; devices inactive for over 30 days are automatically unbound" [101]. The raw OAuth *token* (device-code login) is still not documented for other harnesses; the Console key is the sanctioned bridge. Earlier HN claims that Kimi "cannot be directly integrated into Claude Code" [67] predate this page.
- **Subscription programmatic use — terms**: the Open Platform terms are API-key-centric: they grant a licence to "integrate the Services into your own applications", forbid reselling/transferring API keys, reverse engineering, building competing services, and using content beyond the API, and say Moonshot "may use content to provide, maintain, develop, support, and improve the Services" unless an enterprise agreement restricts training [7]. The consumer/Kimi Code membership terms were **not retrievable** (kimi.com/user/agreement and kimi.ai/legal/terms render only the SPA shell); nothing fetched explicitly permits or forbids driving a Kimi Code subscription headlessly, but Kimi Code CLI's own `-p` mode with OAuth login is a first-party, documented headless path [28][29]. The Open Platform terms (last updated 2026-07-30) do explicitly license API use "to integrate the Services into your own applications, products, or Services (each referred to as a 'Customer Application') and to offer those Customer Applications to End Users", disclaim ownership of outputs ("You are solely responsible for content and we do not claim ownership of it"), and are governed by Singapore law with SIAC arbitration [7][77]. **Consumer agreement recovered (third pass, 2026-09-24)** via the App Store-published URLs [97][98][99]: the Kimi User Agreement (effective 2026-08-31, last updated 08-24) is with **Beijing Moonshot Technology Co., Ltd.** under **PRC (Mainland) law**; it grants Moonshot "A FREE LICENSE TO USE YOUR INPUT, OUTPUT, AND FEEDBACK FOR MODEL OPTIMIZATION" with an opt-out by contacting support; says "you own the intellectual property rights and other rights in your Input and Output"; forbids "copying, transferring, renting, lending, selling, or sub-licensing all or part of the Service"; forbids "Writing or using any automated scripts, programs, or tools (including but not limited to bots, crawlers, scheduled tasks, etc.) to simulate manual operations"; and forbids sharing account credentials or making the account "available to others" [97]. The Paid Services Agreement (same date/entity) makes memberships "non-refundable and non-transferable", defers quota limits to "the actual display of service benefits on the product interface", and lists "concurrent/multi-task capabilities" as a plan benefit without numbers [99]. **Reading for our use**: the bot/scheduled-task clause targets simulating a human in the consumer app; Kimi Code's own `-p` mode and the Kimi Code Console API keys for third-party tools (next bullet) are documented product surfaces, so headless use *through those channels* is sanctioned product behaviour, while scripting the chat web app is not. Outputs are owned by the user, so serving them to third parties is not itself prohibited — the prohibited act is making the *account/Service* available to others. Two caveats: the Beijing-entity text is what the iOS listing links; whether the Singapore entity (kimi.ai) publishes a different international version is unverified as of 2026-09-24 (the same URL served the same text from both hosts), and the membership terms nowhere mention API keys or third-party tools, so the docs page [100] is the only authority on that.
- **Rate limits (API)** [4]: tiers by cumulative recharge — Tier0 ($1): 1 concurrent, 3 RPM, 500K TPM, 1.5M TPD; Tier1 ($10): 15 / 100 / 2M / unlimited TPD; Tier2 ($20): 40 / 100 / 3M; Tier3 ($100): 50 / 200 / 3M; Tier4 ($1,000): 60 / 200 / 4M; Tier5 ($3,000): 100 / 300 / 5M. Web-search QPS is a separate quota (1→50). $1 minimum recharge; a $5 voucher lands when cumulative spend hits $5. Limits may be cut under cluster load. **Tier0's 1.5M TPD caps a 165K-token job at ~9 runs/day — recharge $10 immediately.**
- **Subscription caps**: the official Kimi Code plan page says "Credits reset weekly and are shared across devices" (Plus) and "Ample weekly limits and increased concurrency caps" (Pro) — — **superseded by the membership page (third pass, 2026-09-24)** [101]: for **new plans** "The weekly quota limit is removed — quota no longer refreshes every 7 days. The rolling 5-hour rate window still applies: too many requests in a short time trigger rate limiting"; **legacy plans** keep "Quota refreshes automatically every 7 days from your subscription date, unused quota does not roll over, and the same 5-hour rolling rate window applies"; both share "the Kimi membership monthly total quota: if the monthly total is reached, Kimi Code quota is frozen"; "Go" has no coding quota. So the **5-hour window is official** (no longer community-only), and the live usage endpoint exposes exactly these windows as `limit5h`, `limit7d`, `monthTotal`, `monthCode` with `usedRatio`/`resetAt` [102]. Absolute token sizes per window are still unpublished. Overflow is **Extra Usage** (pay-as-you-go wallet, shared between Kimi and Kimi Code, deducted last): ¥0.03 for "a simple request", ~¥1.6 for "a complex multi-step task", top-ups ¥25 min / ¥3,000 per day / ¥10,000 balance cap [101] [78][57][62]. `/usage` in the CLI shows remaining quota [40]. K3 at 1M ctx burns ~2x the quota of `k3-256k`; HighSpeed burns 3x [39].
- **Usage / quota introspection (programmatic)**: (a) metered API — `GET https://api.moonshot.ai/v1/users/me/balance` returns `available_balance`, `voucher_balance`, `cash_balance` (USD); requests fail with `exceeded_current_quota_error` once `available_balance` ≤ 0. There is no per-window RPM/TPM/TPD remaining-quota endpoint; the console's organisation/project "overview" pages give consumption analytics, and projects carry hard budgets ("any subsequent API requests for that project will be denied") plus per-project TPM caps and IP allow-lists [79][80]. (b) Kimi Code subscription — the `kimi web` server exposes `GET /api/v1/oauth/usage` ("Plan quota and booster wallet of the managed account, fetched live") with `quota.usages[]` entries carrying `usedRatio` and `resetAt` per window and `extraUsage` (pay-as-you-go wallet, `balanceCents`/`totalCents`), `GET /api/v1/oauth/userinfo` (membership level), and `GET /api/v1/sessions/{id}/snapshot` whose `usage` object includes `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `context_tokens`, `total_cost_usd?`, `turn_count?` — all flagged experimental ("endpoints, fields, and event types may change in any release") [31]. (c) Telemetry export: none. Kimi Code has no OTEL/metrics exporter; the only related knobs are `KIMI_DISABLE_TELEMETRY` (anonymous phone-home off) and the `KIMI_LOG_*` file-log rotation vars; `stream-json` per-turn events and the session `wire.jsonl` logs are the exportable record [36][28][30].
- **Sandboxing**: Kimi Code CLI has a permission model (read-only auto-allowed; Write/Edit/Bash need approval unless `--yolo`/`--auto`), `PreToolUse`/`Stop`/`UserPromptSubmit` hooks that can block via exit code 2, symlink-escape blocking and workspace trust (v2.1.0), Bash 60 s foreground / 10 min background timeouts. No OS-level sandbox — it runs as your user [34][37][27].
- **Session resume**: `kimi -c` (most recent in cwd) or `kimi --session <id>`; sessions live in `~/.kimi-code/sessions/<cwd>/<id>/` with `state.json` and `agents/*/wire.jsonl` replayable event logs; `kimi export <id>` zips a session [30].
- **Credential lifecycle (Kimi Code OAuth, from source, 2026-09-24)** [103][104][105][106]: `kimi login` runs a device-code flow against `https://auth.kimi.com` (`/api/oauth/device_authorization`, `/api/oauth/token`; client id `17e5f671-…`) — no browser needed on the box, the URL/code can be approved from any device. Tokens (`access_token`, `refresh_token`, `expires_in`, `scope`) are stored **plaintext JSON, no Keychain**, at `$KIMI_CODE_HOME/credentials/<provider>.json` (dir `0o700`, file `0o600`, tmp→fsync→chmod→rename), MCP OAuth at `credentials/mcp/<key>-<suffix>.json`. **Silent refresh**: `ensureFresh()` refreshes when remaining lifetime < `max(300 s, 0.5 × expires_in)`, 3 retries with 1/2/4 s backoff on 429/5xx/transport errors, 30 s HTTP timeout; cross-process `proper-lockfile` at `<home>/oauth/<provider>.lock` (120 × 0.5–1 s, 5 s stale) so parallel headless sessions don't double-refresh, and a post-lock re-read adopts a peer's newer token. **What fails first**: a 401/403 or `invalid_grant` on refresh writes a **tombstone** (`access_token: ""`) and raises `OAuthUnauthorizedError` → every subsequent `kimi -p` fails until a human re-runs `kimi login`; network errors propagate without tombstoning. The absolute access-token TTL (`expires_in`) and refresh-token lifetime are server-set and **not documented** — our alarm should be "tombstone file present or `/api/v1/oauth/usage` returns 401" rather than a clock. The Console API key path (`api.kimi.ai/coding/`) has no refresh at all (static key in `settings.json`, plaintext) [100]. Multiple instances sharing `KIMI_CODE_HOME` share credentials [36].
- **Streaming**: SSE on both OpenAI- and Anthropic-compatible endpoints; usage separates `cache_read_input_tokens`, `cache_creation_input_tokens`, and `output_tokens_details.thinking_tokens`; optional `X-Msh-Request-Nonce` response signing [8].

- **Finance-specific products / claims**: the K3 blog cites "financial consulting reports", a "42-year ASIC industry analysis via 2,800+ web searches and 1,100+ terminal operations", and persistent "Dashboard and Widgets" for data interaction — knowledge-work marketing, not a finance product [15]. For structured market-data tools (strict `json_schema` arguments, numeric fields, symbol lists) that matters more than for chat. **What the Verifier actually measures (checked 2026-09-24)**: the published methodology has a "K2VV ToolCall" benchmark ("trigger consistency (F1) and JSON Schema accuracy"), but the public K3 results table covers only OCRBench (0.878–0.897), MMMU Pro Vision (0.804–0.820), BEAM-1M (0.2913–0.3219) and DeepSWE (0.658–0.695) across Moonshot, Fireworks, Baseten, Together, DigitalOcean, Inferact, Nebius, Modal and RadixArk — **no per-vendor tool-call fidelity numbers exist for K3, and neither DeepInfra nor Telnyx appears in any Verifier result** [18][89]. Consequently the zero-retention routes recommended in §7/§8 carry an *unmeasured* structured-tool-call risk. Before routing trading research through any of them, run the in-house probe specified in §7 ("Tool-call fidelity probe"), and in all cases validate every tool-call payload against the schema before executing it [74][75][12].
- **Long research runs and compaction**: the K3 README notes Moonshot's BrowseComp 91.2 was obtained with "a context-compaction strategy triggered at 300K tokens"; with the full 1M window and no context management the score is 90.4 [24]. For multi-hour research jobs (earnings sweeps, filings review) plan a compaction step around 300K tokens rather than trusting the 1M window end-to-end; Claude Code users judge Claude's compaction better than Kimi Code's [58].
- **Restrictions**: the Open Platform terms contain no finance-specific clause; they do allow Moonshot to use customer content to improve services absent an enterprise agreement, and bar sanctioned users/regions [7]. For Atlas's proprietary theses that data clause is the material restriction. **Official data-handling facts (2026-09-24)**: Moonshot's privacy policy (MOONSHOT AI PTE. LTD., last updated 2025-04-30) says "We store the information we collect in secure servers located in Singapore", retains "account, input, and payment information ... while your account is active", and uses content to "optimize our models"; the ToS (2026-07-30) adds that content may be used to "improve the Services" with a training restriction available only via "enterprise arrangements or separate written agreements"; a dedicated **Zero Data Retention** page says ZDR ("request content is processed only while the response is being generated and is deleted as soon as the response is returned"; "Enterprise customer data is not used to train models") is "available on request to enterprise customers", excludes direct image/video uploads, security/billing logs and third-party connectors, and keeps automated content-safety review on [7][82][90]. Net: on a pay-as-you-go key, inputs are retained for the account's life in Singapore and are training-eligible; ZDR exists but is enterprise-gated. **Consumer/Kimi Code lane (third pass)**: the consumer Privacy Policy (2026-08-24, Beijing Moonshot Technology Co., Ltd., Haidian, Beijing) says "We store your personal information within the territory of the People's Republic of China", uses conversation content to "optimize our models" with an opt-out on request after identity verification, retains data "only for the period necessary", and shares with payment processors, "advertising partners" and "authorized partners" [98]; the User Agreement adds the model-optimisation licence over input *and output* [97]. So the subscription lane is **worse** than the API lane for proprietary theses: PRC residency, PRC law, training by default, opt-out only by support ticket. Alternatives: route via a third-party host with a no-retention policy — but see the corrected host list in §7 (OpenRouter's ZDR-flagged K3 endpoint is InferenceNet fp4, not DeepInfra; Telnyx is not on OpenRouter) — at the cost of the *unmeasured* tool-call fidelity discussed above [18][75][91]. **Added 2026-09-24**: Anthropic's September allegations (§5 Controversies) — that Moonshot proxied ~300K user requests to Claude under the Kimi brand and collected the exchanges for training — bear directly on this clause: if true, prompts sent to Moonshot-operated surfaces may have been forwarded to a third party without disclosure, and the reported Treasury blacklist talk adds a sanctions-continuity risk to any Moonshot-billed account [68][69][70]. Neither allegation is adjudicated; treat them as unresolved counterparty risk.

## 7. Integration recipe for our server

**Recommended path**: metered API with a platform key, **not** a Kimi Code subscription, because (1) — revised 2026-09-24 — the subscription now *does* have an official Claude Code path (Kimi Code Console API key → `https://api.kimi.ai/coding/` [100]) and a first-party headless CLI (`kimi -p`) [28][29], but its terms are consumer terms: PRC law and residency, training on input+output by default, account non-shareable, and a blanket ban on "automated scripts … scheduled tasks" that only the documented Kimi Code channels arguably fall outside [97][98][99]; (2) subscription quotas are a 5-hour rolling window plus a monthly total with unpublished absolute sizes [101], and were paused/waitlisted this summer [57][58]; (3) the API is cheap at our volumes (§4) and its Anthropic-compatible endpoint lets the existing Claude-Code-shaped harness run K3 with env-var changes only [5][8]. Recharge $10 on day one to leave Tier0 (3 RPM / 1.5M TPD) [4].

**Model routing**: `kimi-k3` (via `/anthropic`, `kimi-k3[1m]` in Claude Code) for research/adversarial review/long agentic runs; `kimi-k2.7-code` (OpenAI-compatible or as the Claude Code "haiku" slot) for coding, structured extraction, and classification — it has the most stable `json_schema` support [12]; K2.7-code/K2.6 **Batch** (60% of list) for overnight bulk classification or ledger annotation [6].

Sketch A — run our existing Claude-Code-style job under Kimi (per-job env, never in `~/.claude/settings.json` because that block overrides shell vars for every job). The official guide lists ten variables and warns that "configuring only some of the variables makes the corresponding scenarios fail silently" — set all of them, including the `FABLE` slot [5]:

export ANTHROPIC_DEFAULT_HAIKU_MODEL='kimi-k2.7-code'

export CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000

Sketch A′ — same harness, but through **OpenRouter** instead of Moonshot's own `/anthropic` endpoint (community-tested: philippdubach, 2026-07-19/08-16, $7.18 for 115 requests) [71]. Point `ANTHROPIC_BASE_URL` at an OpenRouter Anthropic-compatible proxy with the same model-slot variables and pin providers with OpenRouter's `provider` object (`order`, `only`, `allow_fallbacks: false`, `quantizations`, `data_collection: "deny"`, `zdr: true`) [91]. **Corrected 2026-09-24**: OpenRouter's ZDR endpoint list (`/api/v1/endpoints/zdr`) flags exactly one K3 endpoint — **InferenceNet, fp4** ($1.40/$10.75) — and one K2.7-code endpoint (Fireworks) and one K2.6 (Sail Research, int4); **DeepInfra's bf16 K3 endpoint is not ZDR-flagged** (DeepInfra's own privacy policy says "We will not store, sell, or train using this data unless we have your explicit consent", US-hosted, but OpenRouter does not classify it ZDR), and **Telnyx is not an OpenRouter provider at all** — its K3 ("zero data retention", "no training on your data", in-region Americas/Europe/MENA/APAC, $2.70/$13.50) is reachable only directly through its own OpenAI-compatible API [92][93][94][75]. So the realistic zero-retention options are: (i) `zdr: true` on OpenRouter → InferenceNet fp4 (cheapest, quantised, unmeasured tool-call fidelity); (ii) OpenRouter `only: ["deepinfra"]` bf16 with `data_collection: "deny"` (full precision, non-training per DeepInfra policy, but 16.4K max completion and not OpenRouter-ZDR); (iii) Telnyx direct (ZDR + no-training stated, precision unstated, separate key/billing); (iv) Moonshot enterprise ZDR (requires a sales conversation). The trade-off in every case is the unmeasured tool-call fidelity (§6) [18][74][89]. The author's env vars were not published, so verify the slot mapping against the official guide before relying on it.

**Tool-call fidelity probe (required before trading-research routing).** Because no vendor-level tool-call measurement exists for the ZDR routes, run a 200-case probe per candidate endpoint before enabling it: 100 prompts that *should* trigger one of five strict-`json_schema` tools (quote lookup by symbol list, OHLCV window, filings fetch, position-size calc, thesis-ledger write) and 100 that should not; score trigger F1 (mirrors K2VV) and schema validity (strict `jsonschema` validation of `arguments`, numeric types, enum symbols), plus argument exact-match against Moonshot's own `/v1` endpoint as the reference. Accept an endpoint only at ≥0.95 trigger F1 and ≥0.98 schema validity; log per-endpoint results next to the router config so the number is re-checkable when the provider changes quantisation [18][89][12].

Sketch B — direct API tool loop in Python (OpenAI SDK, already a transitive dep) [13][10]:

```python
from openai import AsyncOpenAI
client = AsyncOpenAI(base_url="https://api.moonshot.ai/v1", api_key=os.environ["MOONSHOT_API_KEY"])
msgs = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": task}]
for _ in range(MAX_TOOL_ROUNDS):
    r = await client.chat.completions.create(
        model="kimi-k3", messages=msgs, tools=TOOLS,
        reasoning_effort="high", max_completion_tokens=8192,
        response_format={"type": "json_schema", "json_schema": SCHEMA},  # optional
    )
    m = r.choices[0].message
    msgs.append(m.model_dump(exclude_none=True))   # MUST keep reasoning_content
    if r.choices[0].finish_reason == "length": raise RuntimeError("truncated")
    if not m.tool_calls: break
    for tc in m.tool_calls:
        msgs.append({"role": "tool", "tool_call_id": tc.id, "content": run_tool(tc)})
```

Burden rating: **high** (comparable to Antigravity's 10 releases in 13 days; above Codex weekly). Mitigation: pin the npm version per deploy, regenerate the client from the served `/openapi.json`, and keep the metered-API path (stable OpenAI/Anthropic-compatible surfaces) as the primary.

*Concurrency per lane (parallel headless sessions)* [4][78][99][101][34][36]: metered API — concurrency is the tier's first number: Tier0 **1**, Tier1 **15**, Tier2 **40**, Tier3 **50**, Tier4 **60**, Tier5 **100** concurrent requests (plus RPM/TPM/TPD) — recharge $10 to get 15-wide fan-out. For the scheduler: treat Kimi as **API: 15+ lanes after $10; subscription: 2 lanes**.

*Prompt-injection / sandbox posture (untrusted Telegram text, fetched pages, MCP results)* [34][37][27][10]: Kimi Code CLI **auto-runs `WebSearch` and `FetchURL` in every mode including default and `--plan`** (read-only class), so a fetched page's text reaches the model with no approval gate; `Bash`/`Write`/`Edit` need approval by default and are unguarded under `--auto`/`--yolo`; there is **no OS-level sandbox** (runs as the user; no network allow-list; only `stdin` closed on Bash), no documented injection scanner, no workspace-trust prompt beyond v2.1.0's symlink-escape block; `PreToolUse` hooks (exit 2 blocks) are the only enforcement point, which is why Sketch C mirrors `guards.py` there. The raw API adds built-in `$web_search`/`$url_fetch` whose results are injected as prompt tokens with no provenance marking [11]. Ranking against the other lanes: **below** Codex (Seatbelt) and Claude Code (permission prompts + `verbatim_prompts`), roughly on par with opencode/Perplexity-MCP "auto-run" postures — acceptable for owner-authored tasks in `--auto`, **not** for jobs that ingest Telegram text or arbitrary URLs without a hook-enforced allow-list.

*Host resource budget (16 GB M4)* [110][31][34]: the CLI is a 53.5 MB Node ≥ 22.19 package; resident RAM per `kimi -p` process is **unmeasured** (no published figure; expect a typical Node agent's 150–400 MB, more with `kimi web` + MCP servers + AgentSwarm children, each subagent a further process). Nothing else is always-on: no local proxy, no collector, no model weights (K3 is not local-runnable [65]). Budget one CLI process per concurrent lane and measure with `ps -o rss` on first run; cap `KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY` at 4 on this box.

*Reviewer independence (is a Kimi second opinion uncorrelated with Claude?)* [106][68][69][21][54]: Anthropic alleges two Moonshot distillation campaigns — 3.4M Claude exchanges targeting agentic reasoning, tool use and coding with an explicit attempt "to extract and reconstruct Claude's reasoning traces" (Feb 2026) and ~300K Opus requests proxied under the Kimi brand and collected for training (Sept 2026) — which, if true, means K3/K2.7 were trained partly on Claude outputs, so their error distribution on exactly the tasks we would use them to review (code, tool calls, agentic plans) is **partially correlated with Claude's**, not independent. Counter-evidence: Fireworks' 1,030-task eval shows K3 and Fable winning *different* task families (terminal/security/Rust vs web/Java/Python) [54], which is the signature of at least partially different training, and the architecture (KDA/NoPE MoE) is Moonshot's own [55]. Net: treat Kimi as a **semi-independent** reviewer — useful for catching a different class of errors, not for statistically independent double-checking; prefer it as the second opinion on terminal/security-style work where its own strengths lie, and pair Claude output with a non-Chinese-lab third lane (Gemini/GPT) when independence matters.

*Chat-surface latency comparator* [95][109]: a measured Claude number for the primary Telegram lane is absent from the Claude doc; Artificial Analysis lists **Claude Sonnet 5 (non-reasoning) TTFT 1.26 s, 62.3 tok/s** (its adaptive-reasoning max-effort variant measures 152.5 s TTFT — i.e. effort setting dominates; Opus 5.5 speed not yet measured as of 09-24) [109]. Against that anchor, K2.7-code-highspeed (~180 tok/s vendor, TTFT unmeasured) is the only Kimi SKU that would not feel slower than Sonnet-low; K3 (3.8 s TTFT + always-on reasoning) is 3x slower to first token before any thinking.

*Fit scorecard, calibrated to the cross-doc anchors* (10 = best-in-class lane in the whole study; 5 = usable with workarounds; 1 = unusable): see §8, where the scores are restated against these anchors.

**Task-class fit**: research (deep, browse-heavy) — strong; coding — good with K2.7-code, K3 for long refactors; code review / adversarial review — good and cheap as a second opinion (Fireworks routing data suggests it wins on terminal/security-style tasks) [54]; chat — fine but slow; classification/routing — use K2.7-code batch or `json_schema`; trading research — good for web-sourced synthesis, no market connectors, mind the data clause.

**Gotchas**: replay the full assistant message incl. `reasoning_content` or tool loops break [13]; never switch models mid-session [15]; prefix cache needs >256 prompt tokens and is invalidated by editing earlier tool declarations [10]; K2.7-code needs thinking enabled in Claude Code or it misbehaves [5]; `KIMI_API_KEY` is read from `config.toml [providers.kimi.env]`, not the shell [36]; OpenRouter `:free` IDs have no endpoints [46]; Moonshot's batch is K2.x only — K3 batch exists only via OpenRouter/DeepInfra at 76% of list [6][74]; Tier0 is 1 concurrent request [4]; plan a compaction step near 300K tokens on long runs (Moonshot's own BrowseComp setting) [24]; omitting any of the ten Claude Code env vars fails silently [5]; verbose reasoning can 2–4x the output bill (§4) [52]; open weights (1T–2.8T) are not local-runnable on a 16 GB M4 — the "29 GB RAM at 0.5 tok/s" stunt is SSD streaming, not a workable path [65].

## 8. Verdict

1. K3 is the strongest open-weight model available today (AA #3, arena #17) and is genuinely competitive on terminal/browse-heavy agentic work, at 30% of Claude's list price [47][51][54].
2. Everything is metered-API-first for us: the coding subscription now has an official Claude Code path (Console key → `api.kimi.ai/coding/`) [100], but it runs on consumer terms (PRC law/residency, input+output training by default, no account sharing, bot/scheduled-task ban outside documented channels), a 5-hour rolling window with unpublished sizes, and was paused/waitlisted in July — an owner-only coding lane at most [97][98][99][101][57][58].
3. The Anthropic-compatible endpoint makes it a near drop-in second brain for our Claude-Code-shaped jobs; the OpenAI endpoint plus `json_schema` covers classification and batch [8][12][6].
4. Real costs are inflated by always-on verbose reasoning and slow decode; budget 2–4x the nominal output tokens and expect multi-minute jobs [52][47].
5. Data-use terms (Moonshot may train on inputs) and Chinese jurisdiction mean it should not see Atlas's proprietary signals unless routed through a no-retention host [7]. **Updated 2026-09-24**: Anthropic's September allegations (undisclosed proxying of ~300K Kimi-branded requests to Claude and collection of the exchanges for training; alleged Chinese-military-routed requests) and the reported US Treasury blacklist talk raise this from a data-hygiene preference to a counterparty question. Until either is resolved, route K3 through a non-Moonshot, zero-retention host rather than a Moonshot-billed key — **corrected 2026-09-24**: that means Telnyx direct (not via OpenRouter), OpenRouter `zdr: true` (InferenceNet fp4), or OpenRouter pinned to DeepInfra bf16 with `data_collection: "deny"` (non-training by policy but not OpenRouter-ZDR); note that Telnyx (~10% under list) and the DeepInfra batch route (~24% under list) are cheaper than Moonshot direct; **do not enable any of them for trading research until the §7 tool-call fidelity probe passes**, because no vendor-level tool-call measurement exists for these hosts; and keep an exit plan in case a Moonshot-billed account becomes unusable. As of 2026-09-24 Moonshot has issued no response to either the February (3.4M-exchange) or September (300K-request) allegations and the only rebuttal is a third-party plausibility argument (§5), so counterparty status stays **unresolved**; the allegations also downgrade Kimi from an independent to a semi-independent reviewer (§7) [68][69][70][74][75][87][88][89][92][106][108].
6. K3 is *not* a low-latency model (3.84 s TTFT, 36.7 tok/s, always-on reasoning): fit for research and overnight/batch work, not for any live-data trading loop [47].

Fit scores (1–10, calibrated 2026-09-24 to the cross-doc anchors: 10 = best lane in the whole study on that axis, 5 = usable with workarounds, 1 = unusable): research **8** (BrowseComp-class agentic research; −2 for latency and no market connectors); coding/agentic **7** (K2.7-code/K3 near-frontier, harness less mature than Claude Code); cost efficiency **7** (API: 30% of Claude list, but 2–4x verbose output) / **5** (subscription: now $15–$159 with weekly credits, opaque quota); automation friendliness **7** (stable OpenAI/Anthropic-compatible API + balance endpoint; −3 for no OTEL, experimental server API, 10-release/month churn); trading research **4** (down from 5: data-handling now confirmed training-eligible without enterprise ZDR, the ZDR routes have *unmeasured* tool-call fidelity, counterparty allegations unresolved; capability itself unchanged); interactive chat surface **3** (K3) / **6** (K2.7-code-highspeed); visibility/progress **5** (balance + experimental usage endpoint, no telemetry export); third-party serving **8** (API explicitly licensed for end-user apps) / **2** (subscription: account non-transferable, Service not to be made available to others, bot/scheduled-task ban [97][99]); reviewer independence **5** (semi-independent — distillation allegations vs. divergent task-family wins); prompt-injection posture **4** (web tools auto-run in all modes, no OS sandbox, hooks only); credential-lifecycle friendliness **7** (documented file paths, lockfile-safe silent refresh, tombstone failure mode; TTL undocumented).
