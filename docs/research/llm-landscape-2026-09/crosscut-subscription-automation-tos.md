Positioning in one paragraph: every major vendor now sells a flat-rate consumer/prosumer subscription that *includes* a coding agent (Claude Code, Codex, Antigravity/Gemini CLI, Grok Build) and a separately-priced metered API. All of them meter the subscription with a rolling 5-hour window plus a weekly window, and all of them have, in 2026, either restricted or explicitly priced "non-interactive"/third-party use of the subscription. ## 3. Headless / server automation fit

### 3.1 Anthropic (Claude Max + Claude Code + Agent SDK)

**What the terms say.** Consumer Terms (effective Oct 8 2025) prohibit accessing the Services "through automated or non-human means, whether through a bot, script, or otherwise" *except* "when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it" [1]. The "explicitly permit" carve-out is what Claude Code's docs supply: OAuth "is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications"; "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK" [3]. Third-party *developers* "may not … route requests through Free, Pro, or Max plan credentials on behalf of their users" and may not "collect, store, or intermediate Claude.ai credentials or session tokens" [3]; the Agent SDK page repeats: "Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK" [5]. The Agent SDK itself "is governed by Anthropic's Commercial Terms of Service" [5]. The legal page says this in terms — the restrictions do not "prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" [3] — so a single person running the unmodified `claude` binary / Agent SDK with *their own* subscription on *their own* box is inside the permitted zone; anything that lets other people consume your subscription, or that presents a non-Claude-Code client to Anthropic's servers, is outside it.

**Auth modes for a server.** `claude setup-token` mints a one-year OAuth token for `CLAUDE_CODE_OAUTH_TOKEN`, documented "for CI pipelines, scripts, or other environments where interactive browser login isn't available"; it "requires a Pro, Max, Team, or Enterprise plan" and "can only make model requests" (no Remote Control, no claude.ai connectors) [6]. Credential precedence: Bedrock/Vertex/Foundry → `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY` → `apiKeyHelper` → `CLAUDE_CODE_OAUTH_TOKEN` → profiles → `/login` OAuth [6]. On macOS a locked Keychain (SSH session) falls back to `~/.claude/.credentials.json` mode 0600 [6]. **`--bare` mode does not read OAuth credentials at all** — it needs `ANTHROPIC_API_KEY` or an `apiKeyHelper` — and the docs say `--bare` "will become the default for `-p` in a future release" [7]. That is the single most important forward-looking gotcha for a no-API-key server.

**Caps and how background jobs consume them.** Pro/Max share one pool across claude.ai, Claude Code and IDE plugins [10]; both a 5-hour and a weekly bar exist, plus separate Opus/Sonnet weekly bars ("You've hit your Opus limit") [11][8][83]. `/usage` on a subscription shows attribution by skill/subagent/MCP server and a "Loops" row for scheduled tasks, and flags behaviours ≥10% of usage such as long context or cache misses [8]. Cache lifetime is 1 hour on a subscription but drops to 5 minutes once you are drawing on usage credits [8]. Scheduled tasks, cross-session messages, goal check-ins and agent teammates all resend full context and are named by Anthropic as reasons "usage climbs in a long session" [8]. Usage credits (Pro/Max) are billed "at standard API rates", capped by a monthly spend limit you set, with a $2,000/day redemption cap [12].

**What happens at the limit (v2.1.234+).** In an *interactive* session signed in with a claude.ai subscription, Claude Code now "waits in the open session and continues the task on its own after the limit resets" (`autoContinueAtUsageLimit`, on by default); it re-arms at most twice in a row, does not start a wait on its own when the reset is more than 24 hours away ("a weekly limit can reset days out"), and the menu row can be picked manually from `/rate-limit-options` [89]. Crucially for a scheduler, the wait is **not offered at all** for "background sessions and `-p` runs" or on API keys/usage-based billing [89] — so a headless job that hits a limit simply fails and the orchestrator must own the back-off.

**Routines: the sanctioned first-party non-interactive path.** Routines (`/schedule` in the CLI, claude.ai/code/routines on the web) are "available on Pro, Max, Team, and Enterprise plans", in research preview, and "execute on Anthropic-managed cloud infrastructure" — they clone GitHub repositories, so they have no access to local files [88]. Triggers: schedule (presets or cron via `/schedule update`; "The minimum interval is one hour"), an API trigger (`POST https://api.anthropic.com/v1/claude_code/routines/<id>/fire` with a per-routine bearer token under the `experimental-cc-routine-2026-04-01` beta header; "available to claude.ai users only"), and GitHub events (pull_request, release) [88]. Billing: "Routines draw down subscription usage the same way interactive sessions do", plus "a daily cap on how many runs can start per account"; one-off runs do not count against the daily cap; at the cap or the usage limit, accounts with usage credits on "can keep running routines on metered overage", otherwise runs are rejected [88]. `/schedule` "requires a claude.ai subscription login" and is hidden under a Console API key, profile/federation credential or cloud-provider login [88]. For repo-scoped jobs this is a policy-clean alternative to running `claude -p` on the server: it is Anthropic's own client on Anthropic's own infrastructure.

**Ban-risk mitigations that follow from the record.** One account, one human, unmodified binary, no proxying for others, no identity spoofing, keep the 13-account pattern far away; prefer `claude -p`/SDK over any tool that re-implements the Claude Code client; expect `-p` billing to move to credits or `--bare` to require an API key without notice ("Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice" [3]).

**Orchestration ergonomics.** `--output-format json` returns `result`, `session_id`, `total_cost_usd` (client-side estimate); `stream-json` emits `system/init`, `system/api_retry` (with `error` categories incl. `rate_limit`, `oauth_org_not_allowed`, `account_on_hold`), subagent messages with `parent_tool_use_id`, and a final `result` [7]. `--resume <id>` / `--continue`, `--permission-mode auto|dontAsk|acceptEdits`, `--permission-prompts none` (v2.1.259+), `--max-budget-usd`, SIGTERM → exit 143 with resumable turn [7]. Piped stdin capped at 10 MB [7].

### 3.2 OpenAI (ChatGPT plans + Codex)

Consumer Terms (effective Jan 1 2026) prohibit "Automatically or programmatically extract data or Output" and "circumvent any rate limits or restrictions", and forbid sharing credentials; Business Terms govern the API [27]. Codex is "included across ChatGPT plans" including Free and Go [34]. Auth: "Sign in with ChatGPT" (browser, or beta **device-code** flow for headless boxes, or copying `~/.codex/auth.json`) or API key; Codex cloud requires ChatGPT auth [31]. OpenAI's explicit steer: "Use API key authentication for programmatic Codex CLI workflows, such as CI/CD jobs" and "API Key: Great for automation in shared environments like CI" [31][30] — a recommendation, not a stated prohibition on plan use in `codex exec`. `codex exec` runs non-interactively, `--json` for JSONL events, `-o` for last message, `--output-schema`, `--ephemeral`, `codex exec resume --last`, `--sandbox workspace-write|danger-full-access`, `--ignore-user-config` [32]. The app-server is an open, documented JSON-RPC surface for "deep integration inside your own product" with threads/turns/items and streamed deltas [33]; OpenClaw's docs state "OpenAI explicitly supports subscription OAuth usage in external tools and workflows like OpenClaw" [40] (OpenClaw's claim, undated; no OpenAI page saying this was retrieved — unverified as of 2026-09-24; OpenAI's own pages only say "Use API key authentication for programmatic Codex CLI workflows, such as CI/CD jobs" with no prohibition on ChatGPT sign-in [31]).

Caps: "Local messages and cloud chats share your plan's usage allowance. Weekly limits may also apply." Published 5-hour message bands: Plus — Astra 5–45, Sol 15–150, Luna 350–3,000; Pro 5x — 25–225 / 70–700 / 1,750–14,000; Pro 20x — 100–900 / 300–3,000 / 7,000–56,000 [30]. Support "does not reset ChatGPT or Codex usage limits" [34]. Community record: Pro 20x users reported weekly limits draining "several times faster" in Aug 2026 with no staff reply [37]; a Sep 2026 analysis of 3,808 Codex sessions found goal-mode polling loops consumed 49% of all input tokens and exhausted a $200 Pro weekly limit in a median 25 hours [39]. OpenAI's own pricing page confirms Plus/Pro users who hit limits can "purchase additional credits to continue working without needing to upgrade their existing plan" and that the referral program grants "banked rate-limit resets" that are "usable for 30 days after they're granted" [30]; the claim that the Plus 5-hour window was suspended Jul 12 2026 and restored Aug 25 2026 comes only from a secondary source [38] (unverified as of 2026-09-24).

### 3.3 Google (Gemini app / Gemini CLI / Antigravity / AI Pro)

Google ToS (effective Jul 30 2026) bans "using automated means to access content from any of our services in violation of the machine-readable instructions" and "jailbreaking, adversarial prompting, or prompt injection" [46]; the GenAI Prohibited Use Policy adds "Abuse of, harm to, interference with, or disruption to Google's … infrastructure" and automated high-risk decisions "without human supervision" [47]. The decisive text is Antigravity's (the terms page shows no effective/last-updated date): "Using third party software, tools, or services to access the Service (e.g. using OpenClaw with Antigravity OAuth) is a breach of this Agreement … may be grounds for suspension or termination of your Antigravity and/or Gemini CLI accounts" [51]. Enforcement is real: HN 2026-02-11 "Google bans Gemini/Antigravity accounts used outside of Antigravity/Gemini-CLI" [55] and an HN commenter reporting a Google AI Pro ban for using pi.dev [18]. OpenClaw now says "Google ended consumer Gemini CLI Login with Google access on June 18, 2026" and to "Use an AI Studio API key or Vertex AI instead" [54].

What still works headlessly with a subscription: Gemini CLI "Sign in with Google" remains for "Google AI Pro/Ultra subscribers" and org accounts — the same authentication page also says "Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" for unpaid/Google One users while still listing "individual Google account holders (free and paid tiers)" under Sign in with Google, so the AI Pro/Ultra + org reading is plausible but the page is internally inconsistent (unverified as of 2026-09-24) [49]; headless mode "will use your existing authentication method, if an existing authentication credential is cached", otherwise you must use `GEMINI_API_KEY` or Vertex [49]. Quotas: free Google account 1,000 model requests/day (now Antigravity CLI for unpaid/Google One), AI Pro 1,500/day, AI Ultra 2,000/day, unpaid API key 250/day Flash-only [48]. Antigravity plans: every tier, including "No AI Plan" (a "meaningful quota refreshed weekly"), gets "use of Gemini models including Gemini 3.1 Pro, Gemini 3.8 Flash" as the core agent model and "access to all product features, such as the Scheduled Tasks and the CLI"; AI Pro "high quota, refreshing every 5 hours until weekly limit reached", Ultra "highest" plus third-party models; overages via AI credits at Gemini Enterprise pricing; "There is currently no support for: Bring-your-own-key or bring-your-own-endpoint" [52]. That makes the no-subscription Antigravity CLI a $0 first-party headless surface — usable only as Google's own client (see the breach clause above [51]). Gemini CLI headless exit codes are documented (0 success, 1 general/API error, 42 input error, 53 turn limit exceeded) with JSON fields `response`/`stats`/`error` [50] — useful for a scheduler's retry logic. Gemini API free tier: inputs and outputs "used to improve our products" and may be human-reviewed; paid tier not [43]; specific RPM/RPD are only visible in the AI Studio dashboard, Tier 1 spend limit $10 per 10 minutes [44].

### 3.4 xAI (SuperGrok / Grok Build / API)

Consumer ToS (last updated Sep 11 2026) contain no automation clause, but say rate limits may be imposed "at our sole discretion" and forbid account sharing; the API is under Enterprise Terms; Grok on X is under X's ToS [56]. The AUP (Aug 14 2026) prohibits "Accessing the Services through unauthorized automated or non-human means, whether through a bot, script, or otherwise", "Circumventing any rate limits", and use to "unlawfully buy or sell securities or to provide or receive advice about securities, commodities, derivatives" [57]. The word "unauthorized" leaves room for xAI-sanctioned automation: Grok Build (incl. a terminal client) is on every plan [63], and OpenClaw reports xAI issues OAuth tokens to "eligible SuperGrok or X Premium subscriptions" through xAI's shared OAuth client, with SuperGrok quota shown separately from API credits [65] (OpenClaw's claim; no xAI page confirming third-party OAuth was retrieved — unverified as of 2026-09-24). API: tiers by cumulative spend since Jan 1 2026 (T0 $0 → T4 $5,000), T0 already 150 RPS / 50M TPM on grok-4.5–4.7 [61].

### 3.5 Perplexity

Consumer terms and the Pro help-center article returned HTTP 403 in every form tried (direct, r.jina.ai, web.archive.org) — see §9 "Not found". The API is unambiguous: key-based, tiered by lifetime spend (Tier 0 $0 → Tier 5 $5,000), Agent API 1 QPS at Tier 0, Search API 50 query units/s [68]; Sonar chat completions migrate to the Agent API by 2026-09-27 [66]. #### 3.10a Progress-visibility sink: collector, event schema, dashboard feed

The emitters above speak three dialects (OTLP from Claude Code and Codex; JSONL envelopes from `claude -p --output-format stream-json`, `codex exec --json` and Gemini CLI `--output-format json`; HTTP quota reads from Codex app-server, Kimi `kimi web`, MiniMax `remains`). None of the vendors documents the receiving side, so the sink is ours. Author design, not vendor fact:

| Layer | Choice for a 16 GB M4 already running Postgres + Redis | Why | Budget (author estimate) |
|---|---|---|---|
| Collector | one `otel-collector` (contrib) process, OTLP gRPC :4317 + HTTP :4318, exporters: file (JSONL) + Prometheus remote-write or a Postgres exporter | Claude Code and Codex both emit OTLP natively [102][112]; Codex `otlp-grpc`/`otlp-http` and Claude `OTEL_EXPORTER_OTLP_PROTOCOL=grpc` land on the same port | ~100–200 MB RSS, negligible CPU at our event rate (tens of events/min) |
| Storage | Postgres (already present) — one `agent_events` table keyed by `(lane, job_id, ts)` — rather than a second TSDB; Prometheus optional for the `/metrics` scrape | keeps the dashboard's existing DB the single source; avoids a Grafana/Langfuse daemon | 0 new daemons; Grafana (~150 MB) or Langfuse (Postgres+ClickHouse, >1 GB) only if a dedicated UI is wanted |
| Quota pollers | scheduler-side cron: Codex `account/rateLimits/read` (app-server stdio, one call, exit), Kimi `GET /api/v1/oauth/usage` (needs `kimi web` running, loopback), MiniMax `remains`, Claude via a short interactive probe session whose status-line command writes the JSON to a file [109][111][114][81] | vendor-native numbers where they exist | a few KB per poll |

### 5.2a Reviewer independence: are second-opinion lanes actually independent?

## 7. Integration recipe for our server

Given owner policy (no Anthropic API key, subscriptions over metering, free tiers welcome) and the record above:

1. **Keep Claude Max as the primary lane, but harden it against the two documented cliffs.** (a) Use `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN` in the launchd environment rather than relying on a Keychain login that a locked SSH session cannot read [6]. (b) Never pass `--bare` in job templates (it silently ignores OAuth and will become the `-p` default) [7]; pin the Claude Code version the server runs and gate upgrades on a smoke test that asserts `/status` reports "Login method: Claude account". (c) Parse `stream-json` `system/api_retry` events for `error ∈ {rate_limit, account_on_hold, oauth_org_not_allowed}` and back off the whole scheduler, not the job [7]; the v2.1.234 "wait and continue after the reset" behaviour (`autoContinueAtUsageLimit`, `/rate-limit-options`) is interactive-only and "not offered at all" for `-p` runs and background sessions [89], so the scheduler must read the reset time from the limit error, park the queue until then, and cap re-arms (Claude Code itself stops after two consecutive hits). For *pre-dispatch* gating, harvest `rate_limits.five_hour.*` / `seven_day.*` (percent used, `resets_at` epoch) from a status-line command in a short interactive probe session — the object is populated for Pro/Max subscribers after the first API response and is not available in `-p` output or hook inputs [109][110]; enable OTEL (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, OTLP to the local collector, §3.10a) for per-job token/cost metrics [102]. (d) Budget jobs against the *weekly* bar, and against the post-2026-09-14 bar, not the Aug 2026 boosted one: weekly limits are now +25% over the original baseline (17% lower than August) [84], and the Max 20x multiplier only applies per 5-hour session [85]; keep monthly subscription-side consumption under ~$100–200 API-equivalent (≈100–200 Sonnet-class jobs/month uncached) so usage stays inside what Anthropic calls "ordinary, individual usage" [3][22]; drive `/usage`-style attribution into the dashboard. (e) For repo-scoped jobs that need no local files, prefer a **routine** (`/schedule`, or the `/fire` API trigger with its per-routine bearer token) over a server-side `claude -p`: it runs Anthropic's own client on Anthropic's cloud, draws subscription usage "the same way interactive sessions do", and has a daily run cap plus a 1-hour minimum interval [88]; our launchd scheduler can call `/fire` from a job step. (f) Pin models: Claude Opus 5.5 (launched 2026-09-22; "performs at the level of Claude Fable 5.1 on most work and costs 40% less to run than Opus 5", $4/$20) as the default agentic model, Sonnet 5 ($2/$10; retirement "not sooner than June 30, 2027") for routing/cheap review, Fable 5.1 (retirement not sooner than Sep 1 2027) only for the hardest reasoning [14][91][92].

## 8. Verdict

1. Personal, single-user, unmodified-client automation of a Claude Max subscription is documented and permitted today (the legal page says the rules do not "prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" [3]; the programmatic-credit carve-out is paused and Anthropic is "working to update the plan" [4b]), but Anthropic has shown it will re-price or re-gate non-interactive use without notice; design for the OAuth path to disappear and keep routines as the fallback lane.
2. OpenAI is the most tolerant vendor in writing and practice for plan-backed headless Codex use; Google is the least (written breach + bans); xAI and Perplexity are unknowns on the consumer side.
3. Weekly caps, not 5-hour windows, are the binding constraint for a scheduler — more so since the 2026-09-14 re-basing (+25% over the original baseline, 17% below August's boosted level [84]) and given that the Max 20x multiplier is per-session only [85]; polling loops and long idle contexts are the documented ways subscriptions get burned and accounts get flagged. A reported 2026-09-22 move by Anthropic to sell limit resets "like Codex" [93] would soften this (unverified as of 2026-09-24). For unattended jobs the auto-continue-at-reset feature does not apply to `-p` runs [89]; routines are the first-party answer for repo-scoped work [88]. Progress visibility is better than the second pass claimed: Claude (status-line `rate_limits`), Codex (`account/rateLimits/read`), Kimi (`/api/v1/oauth/usage`) and MiniMax (`remains`) all expose window-used percentages and reset times; the missing piece is our collector and event table, not vendor APIs (§3.10–3.10a). Concurrency per lane is unpublished for Claude, Codex, Gemini/Antigravity and Grok Build (§3.10b), so fan-out must be learned from our own rate-limit telemetry.
4. Multi-account scaling is the one pattern with a confirmed permanent ban; one plan per human, always.
5. The cheapest *legitimate* capacity for bulk low-stakes tokens is metered — but under owner policy (no standalone API keys) the metered capacity that qualifies is the kind bundled into a subscription: Ollama Cloud Pro ($20 buys $60 of credits, no training/logging [100]) and Mistral Pro ($14.99 buys $15 [95]). This reconciles with runtimes-aggregators.md verdict 2 ("Ollama Cloud Pro"): that doc ranks by $/token under policy, this one previously ranked by raw $/token ignoring policy. Ranking now: Ollama Cloud Pro → Mistral Pro credits → (if policy relaxes) Luna / 3.8 Flash / GLM-5.3-Flash / DeepSeek-Flash off-peak [35][42][73][98]; never more consumer seats.
