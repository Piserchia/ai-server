## 1. Snapshot

**Company.** Anthropic PBC (San Francisco). Sells (a) the Claude API and "Claude Platform" (Console, Managed Agents, `ant` CLI), (b) consumer/prosumer subscriptions (Free/Pro/Max) and seat plans (Team/Enterprise) that bundle the Claude apps, Claude Code, Cowork, Chrome, Excel, and (c) the same models through Amazon Bedrock, Google Cloud, Microsoft Foundry and "Claude Platform on AWS" [1][2].

- Modalities: all four take text + images and output text; PDFs are accepted as `document` blocks (32 MB per request / 600 pages when the request's context window is 1M tokens, 100 pages otherwise) [1][2][55]. No audio/video input; no image generation.
- Thinking: adaptive and always-on for Fable 5.1 and Opus 5.5 (cannot be disabled), adaptive by default for Sonnet 5, legacy `budget_tokens` on Haiku 4.5. Effort levels `low|medium|high|xhigh|max`; default `high` on Fable 5.1/Sonnet 5, `medium` on Opus 5.5 [2][55]. Opus 5.5 breaking changes vs Opus 5: thinking cannot be disabled (400 on `disabled`/`enabled`), forced `tool_choice` (`any`/`tool`) returns 400, thinking blocks are bound to model + conversation prefix, `computer_20251124` is rejected on the Claude API/Google Cloud (Bedrock still accepts it), and inter-tool-call text now comes back in `thinking` blocks (empty at default `display`) [57].
- Still-served legacy models: Fable 5, Opus 5 (both mid-2026), Opus 4.8/4.7/4.6/4.5, Sonnet 4.6/4.5 [2]. Near-term tentative retirements (all "not sooner than"): Sonnet 4.5 2026-09-29, Haiku 4.5 2026-10-15, Opus 4.5 2026-11-24; Opus 4.6 2027-02-05, Sonnet 4.6 2027-02-17, Opus 5 2027-07-24 [56]. Claude Mythos 5.1 = Fable 5.1 with cyber/bio safeguards lifted, invitation-only via Project Glasswing [1][3][43].
- Seed values check: Fable 5.1 $10/$50 and Sonnet 5 $2/$10 and Haiku 4.5 $1/$5 confirmed [1]. **Opus 5 $5/$25 is stale**: Opus 5.5 replaced it on 2026-09-22 at $4/$20 with $0.20 cache reads [1][5]. Sonnet 5's "introductory" $2/$10 was made permanent; the scheduled 2026-09-01 rise to $3/$15 was cancelled [1].

**Release cadence.** Roughly one flagship every 4–8 weeks in 2026: Mythos Preview (Apr 7), Fable 5 / Mythos 5 (Jun 9), Sonnet 5 (Jun 30), Opus 5 (Jul 24), Fable 5.1 (Sep 1), Opus 5.5 (Sep 22) [3][4][5][43]. Each generation has changed API semantics (thinking modes, forced tool use removed on Fable 5.1, new tokenizer since Opus 4.7 that produces ~30% more tokens) [1][3][55].

**Positioning.** Anthropic's lineup is the current leader on agentic-coding and computer-use benchmarks (Terminal-Bench 4.0, OSWorld 2.0, GDPval) and on the Artificial Analysis Intelligence Index (Opus 5.5 at 58, "the highest score we have measured by several points"; the "five points clear of GPT-6 Astra" margin is unverified as of 2026-09-24) [5][37]. Its distinctive bet is the "harness" layer: Claude Code (CLI/desktop/web/mobile), the Agent SDK (Claude Code as a library), routines, cloud sessions, channels and Managed Agents. The trade-offs are premium pricing at the top tier, opaque subscription caps, a heavy 2026 outage record, and a consumer-terms grey zone around programmatic use of subscriptions (section 3).

## 3. Headless / server automation fit

**Non-interactive modes.**
- `claude -p "<prompt>"` with `--output-format json|stream-json`, `--json-schema '<schema>'` (typed `structured_output` field), `--allowedTools "Read,Edit,Bash(git diff *)"`, `--permission-mode auto|acceptEdits|dontAsk|plan|bypassPermissions`, `--permission-prompts none` (v2.1.259+, denies anything that would prompt and removes `AskUserQuestion`), `--max-turns`, `--max-budget-usd`, `--append-system-prompt`, `--mcp-config`, `--continue`, `--resume <session_id | /path/to/transcript.jsonl>`, `--verbose --include-partial-messages` for token streaming, `--forward-subagent-text`. Exit code 0 on success, 143 on SIGTERM; stdin capped at 10 MB [14].
- `--bare` skips hooks/skills/CLAUDE.md/MCP discovery and is "the recommended mode for scripted and SDK calls" **but never reads OAuth credentials or `CLAUDE_CODE_OAUTH_TOKEN`; it requires `ANTHROPIC_API_KEY`** — so a subscription-only server cannot use `--bare` [14][15]. **Watch item:** the same page says `--bare` "is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release" — if that default lands, an un-flagged `claude -p` on this box would stop reading the subscription OAuth credential and fail on auth. Pin the CLI/SDK version and diff the headless page's `--bare` note on every upgrade; if a `--no-bare` opt-out ships, add it to every scripted invocation [14].
- Agent SDK (Python): `query(prompt, options=ClaudeAgentOptions(...))` for one-shots, `ClaudeSDKClient` for multi-turn with `interrupt()`. Options include `model`, `fallback_model`, `effort`, `max_turns`, `max_budget_usd` (client-side estimate), `permission_mode`, `allowed_tools`/`disallowed_tools`, `can_use_tool` callback, `resume`/`fork_session`/`continue_conversation`, `output_format={"type":"json_schema",...}`, `system_prompt` presets, `mcp_servers` (incl. in-process `create_sdk_mcp_server`), `hooks`, `setting_sources`, `cwd`, `env`, and `verbatim_prompts` (0.2.158+, disables `@path` expansion and slash-command dispatch for untrusted text) [16][29].
- Event/JSON output for orchestration: `system/init` (model, tools, `mcp_servers`, `mcp_server_errors`, `plugin_errors`, `capabilities`), `system/api_retry` (with `error` category such as `rate_limit`, `overloaded`, `oauth_org_not_allowed`, `billing_error`), `assistant`/`user` messages with `parent_tool_use_id` for subagents, and a final `result` with `session_id`, `num_turns`, `total_cost_usd`, `usage`, `model_usage`, `permission_denials` [14][17].

**Auth modes (precedence high→low) [15]:** cloud-provider env vars → `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY` → `apiKeyHelper` → `CLAUDE_CODE_OAUTH_TOKEN` (one-year token from `claude setup-token`, "for CI pipelines, scripts… requires a Pro, Max, Team, or Enterprise plan"; model requests only, no connectors/Remote Control) → Anthropic profiles/federation credentials (only when named via `ANTHROPIC_PROFILE` or federation env vars; an unnamed `user_oauth` profile written by `ant auth login` ranks BELOW a working `/login`) → `/login` subscription OAuth. macOS stores the `/login` credential in Keychain, falling back to `~/.claude/.credentials.json` (0600) when the Keychain is locked (e.g., SSH/launchd); `/login` credentials expire and Claude Code warns 3 days ahead (`Login expired · Please run /login`) [15]. The `ant` CLI's `ant auth login` is an OAuth login to a **Console/API organization** (workspace-scoped token), not to a consumer subscription, and Anthropic says to use Workload Identity Federation, not interactive login, for servers [26].

**May a consumer subscription be used programmatically? (contested, evolving)**
- Consumer Terms (effective 2025-10-08): prohibited "except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means" [12].
- 2026-02-19/20: Anthropic's Claude Code legal page said using Free/Pro/Max OAuth tokens "in any other product, tool, or service — including the Agent SDK — is not permitted"; OpenCode removed subscription auth citing Anthropic legal requests [30].
- 2026-04-04: active blocking of third-party harnesses (OpenClaw etc.) on Pro/Max billing [31][33].
- 2026-05-13/14: Anthropic reinstated third-party/Agent SDK/`claude -p` use on subscriptions, to be metered from a separate monthly "Agent SDK credit" ($20 Pro / $100 Max 5x / $200 Max 20x) from 2026-06-15, overflow at API rates via usage credits [10][31][32].
- **2026-06-15 (current state): that change was paused.** Help Center: "Update June 15: We're pausing the changes to Claude Agent SDK usage described below. For now, nothing has changed: Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits." [10]. Zed confirms the postponement [32].
- Current legal page (fetched 2026-09-24): OAuth "is intended exclusively for purchasers of… subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications"; developers building products "should use API key authentication"; Anthropic "does not permit third-party developers to offer Claude.ai login… or to route requests through Free, Pro, or Max plan credentials on behalf of their users"; "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK"; it "does not prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" [11]. The Agent SDK overview carries the same note about third-party developers [13].
- Reading for this server: single-tenant, owner's own account, Anthropic's own harness (Agent SDK / `claude -p`), no resale — the pattern Anthropic's own docs describe (`claude setup-token` "for scripts") and meter against the plan [10][15]. Heavy 24/7 automation is exactly what triggered the April crackdown, and Anthropic "reserves the right to take measures… without prior notice" [11]. Treat as tolerated-but-revocable; keep the design portable to an API key or usage credits.

**May subscription outputs be served to other people (pickem dashboard, shared project sites)?** The Consumer Terms assign output rights to you and only forbid products that "compete with our Services… or resell the Services" and automated access outside an API key "or where we otherwise explicitly permit it" [12]; the Claude Code legal page forbids routing requests "through Free, Pro, or Max plan credentials on behalf of their users" and says developers "building products or services that interact with Claude's capabilities… should use API key authentication" [11]. Reading: content the owner generates (a rendered league page, a deployed site) may be published; a surface where a second person's request is answered live by the Max account (a public Telegram bot, a chat widget) is the "on behalf of their users" pattern and belongs on an API key. No "personal, non-commercial" clause applies to paid consumer plans (only to evaluation access) [12].

**Rate limits and caps.**
- Subscription: rolling 5-hour session window + weekly cap across all models, plus model-family messages ("You've hit your Opus limit"); exact token budgets unpublished [8][23]. Community anchor (Anthropic's Aug 2025 guidance, since revised): Max 20x ≈ 240–480 h Sonnet + 24–40 h Opus per week (unverified/stale) [35]. Timeline: weekly caps added 2025-08-28 and May 6 2026 permanent 2× on 5-hour Claude Code limits (both unverified as of 2026-09-24 — secondary explainx timeline only); 50% weekly boost May 13–Sep 13 2026; from Sep 14 2026 weekly Claude Code limits are +25% vs the pre-promo baseline, i.e. "a 17% reduction" vs the promo ("Anthropic's own words") [34][35]. Usage credits (Pro/Max) continue past caps at standard API rates, $2,000/day redemption limit, cache TTL drops from 1h to 5m while on credits [9][23]. Routines and cloud sessions draw from the same allowance and add a daily routine-run cap [18][19].
- **Concurrency on the subscription (parallel `-p`/SDK sessions): no published cap.** Searched Anthropic's Max-plan article, usage-limit best practices, costs, headless, cloud-sessions and common-workflows pages on 2026-09-24: none states a maximum number of simultaneous local sessions. Parallelism is documented as a supported pattern — `claude --worktree <name>` "in a second terminal to start an isolated parallel session" [79]; `--cloud` tasks "all run simultaneously in separate sessions" [19]; agent teams "spawn multiple Claude Code instances, each with its own context window" [23] — and the only stated consequence is budget, not admission control: "cloud sessions share rate limits with all other Claude and Claude Code usage within your account. Running multiple tasks in parallel consumes more rate limits proportionately" [19]. Anthropic's per-user API sizing table (1–5 users → 200–300k TPM, 5–7 RPM each) is the nearest published throughput anchor, but it applies to Console orgs, not Pro/Max [23]. Design consequence for the scheduler's fan-out: treat Max concurrency as bounded only by the 5-hour/weekly token budget plus 429/`overloaded` back-pressure (`system/api_retry` events), and pick the fan-out width empirically — start at 3–4 parallel jobs, raise while `rate_limit` retries stay rare. Contrast: Ollama Cloud 1/3/10, Kimi 1–4, MiniMax "3–4 agents", Z.ai "1–2 projects" publish hard caps; Claude Max, ChatGPT/Codex, Gemini and Copilot do not.
- **Credential lifecycle on a headless box [15]:** (i) `/login` OAuth: stored in macOS Keychain, or `~/.claude/.credentials.json` (0600) when the Keychain rejects the write (locked, SSH, launchd) — `CLAUDE_CONFIG_DIR` relocates the file and keys the Keychain entry. Claude Code refreshes it silently without a browser until the refresh token itself expires; the login lifetime is **not published** ("The login lifetime itself is unchanged"), a warning fires 3 days out (v2.1.203+; 5 days before 2.1.217) and only in interactive sessions, and after expiry every model request fails with `Login expired · Please run /login` (a model error before 2.1.206); `/status` shows `Login: Expired — log in again` (v2.1.210+). "A background session… that outlives the login stops making progress once the credential expires and can't recover until you sign in again." (ii) `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`: one-year, printed once, never saved by the CLI, model requests only (no Remote Control, no claude.ai connectors, no `/schedule`), refuses `--bare`. (iii) `apiKeyHelper`: re-run every 5 min (`CLAUDE_CODE_API_KEY_HELPER_TTL_MS`), failures surface within three attempts (v2.1.208+). (iv) Anthropic profile (`ant auth login` / keyless Console sign-in) in `~/.config/anthropic`: auto-refreshed; on failure `Anthropic profile login expired`. **What fails first:** the `-p` lane gets no 3-day warning, so the first symptom is a job result whose stdout is the login-expired text with a non-zero exit, or `system/api_retry` with `error: "authentication_failed"`. Alarm recipe: a daily `claude -p 'ping'` canary plus a calendar reminder 11 months after each `setup-token`; keep both credentials (Keychain login + env token) so one expiring does not stop the box.
- API: tiers by spend history — Start ($500/mo cap), Build ($1,000), Scale ($200,000), Custom. Start-tier per-model limits: Opus 5.5 / Sonnet 5 / Haiku 4.5 1,000 RPM, 2M input TPM, 400k output TPM; Fable 5.x 1,000 RPM, 500k ITPM, 100k OTPM (shared across Fable 5 and 5.1). Cache reads don't count toward ITPM [24].

**Sandboxing.** Claude Code permission modes (`auto` = classifier reviews actions; `dontAsk`; `acceptEdits`), `--allowedTools` prefix rules, `PermissionRequest` hooks, `can_use_tool` callback; cloud sessions/routines run in isolated Anthropic VMs with a domain allowlist and credentials held outside the sandbox [14][16][19]. Managed Agents run in Anthropic containers or self-hosted sandboxes [25]. A local OS-level Bash sandbox feature exists in Claude Code (unverified this session).

**Session resume / streaming.** Sessions are `.jsonl` transcripts resumable by ID from any directory (v2.1.223+), forkable (`fork_session`), and since v2.1.277 resumed runs report the whole session's cumulative cost [14][17]. Streaming: `stream-json` (CLI) / `include_partial_messages` (SDK) / native SSE on the API [14][16].

## 7. Integration recipe for our server

**Recommended path (subscription-first, API-key-free):**
1. Auth: on the Mac Mini run `claude auth login` once with the Max account (Keychain), and additionally mint `claude setup-token` → store `CLAUDE_CODE_OAUTH_TOKEN` in the launchd job's environment so runs survive a locked Keychain; renew yearly and alert on `system/api_retry` with `error: "authentication_failed"` or `oauth_org_not_allowed` [14][15]. Do **not** pass `--bare` (it ignores subscription auth) [14]. Never set `ANTHROPIC_API_KEY` (it outranks OAuth) [15].
2. SDK: pin `claude-agent-sdk==0.2.159` (bundles CLI 2.1.281; `verbatim_prompts` needs CLI ≥2.1.248); drive jobs with `query()`; turn on `verbatim_prompts=True` for any prompt built from Telegram/web input; use `setting_sources=["project"]` so `~/.claude` hooks on the box don't leak into jobs [16][29].
3. Routing by task class (all on the same subscription, but Opus/Sonnet limits are metered by family) [2][23]:
   - classification/routing, log triage: `claude-haiku-4-5` (note retirement not sooner than 2026-10-15; plan the swap to Sonnet 5 at `effort="low"`).
   - research, chat, bulk summarisation: `claude-sonnet-5`, `effort="medium"`.
   - coding, build/deploy loops, code review: `claude-opus-5-5` (default `medium`; use `xhigh` for hard refactors).
   - adversarial review, planning, trading-research theses: `claude-fable-5-1` at `effort="high"`, or Opus 5.5 at `max` when cost matters (community: "plan with fable, implement with opus") [42].
4. Overflow: enable usage credits on the Max account with a monthly spend limit rather than an API key; credits bill at API list price and drop cache TTL to 5m [9][23].
5. Version pins and September platform betas to track: Claude Code 2.1.281 (2026-09-23) is the current CLI (2.1.280 introduced Opus 5.5 as the default Opus; 2.1.278 made server-side classifier the auto-mode default; 2.1.277 added AGENTS.md support — read when a project has no CLAUDE.md, not yet on Bedrock/Vertex/Foundry) [59]. On the raw API (only relevant if the API-key path is ever exercised): compaction on demand (`compact-2026-09-04` beta; top-level `compaction` parameter returns a signed `compaction` block that replaces summarised messages, kept thinking can stay valid) and inline tool definitions in mid-conversation system messages (`inline-tools-2026-09-15` beta; `tool_addition` block carrying a full `tool_definition`, no `tools` edit and no cache invalidation) [57][60].

**Minimal Python sketch:**

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

SCHEMA = {"type": "object", "required": ["verdict", "findings"],
          "properties": {"verdict": {"type": "string"}, "findings": {"type": "array"}}}

async def run_job(prompt: str, cwd: str, model: str = "claude-opus-5-5"):
    opts = ClaudeAgentOptions(
        model=model, effort="medium", cwd=cwd,
        permission_mode="auto",                      # classifier reviews; or "dontAsk" for read-only jobs
        allowed_tools=["Read", "Grep", "Glob", "Bash(git diff *)", "Bash(pytest *)"],
        max_turns=40, max_budget_usd=3.0,            # advisory client-side estimate
        output_format={"type": "json_schema", "schema": SCHEMA},
        setting_sources=["project"], verbatim_prompts=True,
        env={"CLAUDE_CODE_PROMPT_CACHE_TTL": "1h"},
    )
    async for msg in query(prompt=prompt, options=opts):
        if isinstance(msg, ResultMessage):
            return {"session": msg.session_id, "cost_est": msg.total_cost_usd,
                    "reason": msg.terminal_reason, "out": msg.structured_output
                    if hasattr(msg, "structured_output") else msg.result}

print(asyncio.run(run_job("Review the staged diff for correctness bugs.", "/srv/project")))
```

CLI equivalent for shell-driven jobs: `claude -p "$PROMPT" --output-format json --json-schema "$SCHEMA" --permission-mode auto --permission-prompts none --allowedTools "Read,Grep" --max-turns 40 | jq '.structured_output'`; resume with `--resume "$(jq -r .session_id last.json)"` [14].

**Task-class fit here:** research (web search included in Claude Code) — strong; coding/build/deploy — strongest; code review (`gh pr diff | claude -p --append-system-prompt ...`) — strong; chat via Telegram — fine through your own bot, or channels if you want a persistent interactive session; classification/routing — use Haiku/Sonnet, structured output; adversarial review — Fable 5.1; trading research — good analysis, bring your own data tools via MCP.

**Optional cloud complements:** routines (cloud, GitHub-repo based, API trigger `POST https://api.anthropic.com/v1/claude_code/routines/<id>/fire` with a per-routine bearer token and beta header `experimental-cc-routine-2026-04-01`; results as sessions/PRs; draws from plan usage) for jobs that must run when the Mini is down [18]; Managed Agents scheduled deployments only if an API key is ever allowed ($0.08/session-hour + tokens) [1][25].

**Gotchas.**
- Weekly caps are opaque; watch for `rate_limit` retry events and "You've hit your weekly limit"; `autoContinueAtUsageLimit` / `/rate-limit-options` can wait for reset [23].
- `total_cost_usd` is a client-side list-price estimate, meaningless for billing on a subscription; use it only as a relative budget signal [17].
- Fable 5.1 rejects forced `tool_choice` (`any`/`tool`), binds thinking blocks to the producing model, and 400s on edited history for accounts created on or after 2026-08-31 (older accounts only record the mismatch unless `thinking.block_binding.prefix_mismatch_behavior` is set) — keep transcripts append-only [3][55].
- Tokenizer change since Opus 4.7 (~30% more tokens) inflates counts vs older models [1].
- Subscription cache TTL is 1h in-plan, 5m on usage credits or API keys [17][23].
- Policy risk: Anthropic can re-enable the Agent SDK credit split or block patterns "without prior notice" [10][11]; keep an env-var switch to an API key or another vendor.
- Outage risk: multi-day Fable degradation in Sep 2026; use `fallback_model="claude-opus-5-5,claude-sonnet-5"` and expect 529/overloaded during launches [16][44].
- Haiku 4.5 may retire from 2026-10-15; Sonnet 4.5 "not sooner than 2026-09-29" and Opus 4.5 "not sooner than 2026-11-24" are the other near-term legacy retirements (Opus 5 not sooner than 2027-07-24) [2][56].
- **`--bare` may become the `-p` default** ("will become the default for `-p` in a future release"); bare mode never reads OAuth, so on that release every scripted call on a subscription-only box breaks until an opt-out flag is added. Treat every Claude Code/Agent SDK upgrade as a potential auth break; smoke-test `claude -p 'ping' --output-format json` after each pin bump [14].
- **Opus 5.5 response-shape changes** (also relevant when Claude Code/SDK is driven via the raw API): `computer_20251124` is rejected on the Claude API and Google Cloud (use `computer_toolset_20260801`; Bedrock still accepts the old tool), and the short text the model writes between tool calls now arrives as progress-update `thinking` blocks whose text is empty at the default `thinking.display: "omitted"` — a job-progress UI that streams inter-tool text goes silent between tool calls with no error unless `thinking.display` is set. Select content blocks by `type`, never by position [57].
- **Life Sciences Verification Program** (announced 2026-09-17): biology-domain work on Mythos/Opus/Sonnet with relaxed safeguards requires organisational enrollment (Standard Use, annual renewal; High-risk Use add-on, six-month renewal, per project); available on Enterprise/Team via Claude Science, claude.ai, Claude Code and the API, individual plans "pending". Opus 5.5 runs a biology classifier in addition to the cyber one, so unenrolled bio requests can return `stop_reason: "refusal"` (category `bio`) — the cyber fallback to Opus 4.8 is not the only safeguard path [57][58].

The `opus` alias on 2.1.273 resolves to `claude-opus-5`, not 5.5 (2.1.280 is where Opus 5.5 became the default Opus [59]). ## 8. Verdict

1. Anthropic currently has the strongest agentic-coding and computer-use models (Opus 5.5 leads the AA index and Terminal-Bench 4.0 [5][37]) and the most complete headless harness (Agent SDK, `claude -p`, routines, channels).
2. For this server the cheapest legitimate path stays the Max subscription driving the Agent SDK/`claude -p`, which Anthropic's Help Center says "still draw from your subscription's usage limits" after the June 15 pause [10] — but the Consumer Terms/legal page language remains conservative and enforcement history is volatile [11][30][31], and the documented plan to make `--bare` (API-key-only) the `-p` default is a forward breakage risk to watch on every CLI/SDK upgrade [14].
3. Opus 5.5 ($4/$20) is the new default; Fable 5.1 ($10/$50) is for adversarial review and hard planning; Sonnet 5 ($2/$10) and Haiku 4.5 ($1/$5) for volume [1].
4. Reliability is the weak spot: 200+ tracked incidents in 2026 and a 3-day Fable degradation in September [44][45]; design for fallbacks.
5. Finance: excellent analyst, no data feed; bring market data via MCP and keep execution out of the model's hands [46].

Fit scores (1–10): research **9**; coding/agentic **10**; cost efficiency **7** (subscription 9, API 5); automation friendliness **8** (docs/harness 10, terms/caps 5); trading research **6**.

Calibration anchors for the cross-provider scorecard (so the router can compare like with like): 10 = best-in-class on a public benchmark the doc cites (Terminal-Bench 4.0 / AA index for coding); cost 9 = flat-fee subscription covering ≥100 Opus-class jobs/month, 5 = list-price API at $4/$20; automation 8 = documented headless CLI + SDK + structured output + OTEL, minus 2 for unpublished caps and revocable subscription terms; trading 6 = strong analyst with zero native data/execution and 30-day minimum retention on Fable. Two dimensions added for the cross-cut: **data handling 5** (30 d retention, no ZDR/residency on the subscription lane, Fable always 30 d) and **progress visibility 7** (stream-json + OTEL on subscription; plan gauge only via status-line JSON, no REST). **Chat-surface latency 6** (Sonnet 5 low/medium measured ≈2 s wall, 3–6 s tails, on this box; Opus 5.5 unmeasured; flagships not interactive). **Concurrency (new dimension) — unpublished/unbounded-by-policy**: no session cap on Max, only proportional budget draw [19][23][79]; score as "no hard cap, budget-limited" rather than a number. **Trading-terms posture 4**: Consumer Terms securities/not-a-broker-dealer clause [12] plus Usage Policy high-risk finance review [82] mean the subscription lane may research, not decide.
