# Driving this server FROM the vendors' own apps: custom MCP connectors, ChatGPT apps/connectors, Gemini extensions, Claude connectors/channels, Telegram/Slack bots — research (as of 2026-09-24)

Reader: single-tenant assistant server on a Mac Mini M4 (Python 3.12, Claude Agent SDK on Claude Max, Postgres/Redis, Telegram bot + web dashboard, launchd, Cloudflare Tunnel + Caddy; ~30–60 agent jobs/day; Atlas paper-trading loops, no live order path). Question: how does the owner **launch jobs, query status and receive deliverables** from inside claude.ai, Claude Code, ChatGPT, Gemini/Antigravity, Grok, Perplexity, Cursor and iOS Shortcuts, and which surfaces give a real "one server, many front doors" experience today.

## 1. Snapshot

**The category.** Every major assistant is now an **MCP client**: it can call tools on a remote MCP server the owner hosts, over Streamable HTTP (SSE is legacy), authenticated with OAuth 2.1 (PRM + AS metadata + PKCE; CIMD for client registration — DCR is deprecated in the current 2026-07-28 revision but remains supported for ASes without CIMD [60][61]) or, in developer tools, a static bearer/service-token header [40][41]. The "reverse direction" therefore reduces to: (a) expose one MCP endpoint (`https://mcp.<domain>/mcp`) from the Mac Mini through the existing Cloudflare Tunnel, (b) register it once per vendor app, (c) add push paths (Telegram/iMessage/Slack, Claude mobile push) for deliverables, because MCP itself is pull-only from the client's point of view.

**Positioning.** Anthropic is the only vendor whose consumer app (claude.ai on web/desktop/mobile), coding agent (Claude Code), cloud runner (routines with an HTTP trigger), live Artifacts dashboards and phone app (Remote Control + push, cross-session messaging) all consume the **same** connector registration and the **same** Max subscription the server already runs on. ChatGPT is a strong second front door (dev mode is genuinely a full read/write MCP client on Plus), but web-only and pull-only. Gemini/Grok/Perplexity consumer apps have no documented custom-MCP path; their CLIs/APIs do. iOS Shortcuts is the cheapest "one tap → job" launcher but needs plain HTTPS, not MCP.

## 2. Interfaces & surfaces

**Protocol baseline (current MCP revision is 2026-07-28; the 2025-06-18 authorization model and 2025-11-25 additions below still apply, but 2026-07-28 makes the protocol stateless — no `initialize` handshake, no `Mcp-Session-Id`, per-request version in `_meta`, mandatory `server/discover`, `subscriptions/listen` replaces the GET stream, `Mcp-Method`/`Mcp-Name` headers required on Streamable HTTP POSTs — deprecates DCR in favor of CIMD, formally deprecates HTTP+SSE, and moves tasks to an extension [60][61]).** MCP servers on HTTP "MUST implement OAuth 2.0 Protected Resource Metadata (RFC 9728)"; clients "MUST use" it for AS discovery; ASes "MUST provide" RFC 8414 metadata; "MCP clients MUST implement PKCE"; clients "MUST implement Resource Indicators (RFC 8707)"; tokens go in `Authorization: Bearer`, "MUST NOT be included in the URI query string"; servers "MUST validate that access tokens were issued specifically for them"; token passthrough is forbidden [40]. 2025-11-25 adds OIDC discovery, **Client ID Metadata Documents (CIMD)** as recommended registration, incremental scope consent, URL-mode elicitation, experimental **tasks** for long-running requests, and 403 for bad `Origin` on Streamable HTTP [41]. Streamable HTTP is the transport every vendor now recommends; Claude Code marks SSE "Deprecated" [6] and ChatGPT says "Deploy production MCP servers at stable HTTPS endpoints using the streamable HTTP transport" [28].

**What 2026-07-28 means for the FastMCP front door.** Requests are now self-describing: each carries `io.modelcontextprotocol/protocolVersion` and client capabilities in `_meta` (also the `MCP-Protocol-Version` header on Streamable HTTP), there is no `initialize` handshake or `Mcp-Session-Id`, and any cross-call state must be an explicit server-minted handle passed as a tool argument — fine for `list_jobs`/`get_job`, which are naturally stateless [60][61]. The server MUST implement `server/discover` (versions, capabilities, identity); Streamable HTTP POSTs must carry `Mcp-Method` and `Mcp-Name` headers (a `HeaderMismatchError` otherwise); `tools/list` and friends must return `ttlMs` and `cacheScope` (`public`/`private`) — set `cacheScope: "private"` on this server since responses are per-owner; every result carries `resultType: "complete"`; the GET notification stream is replaced by `subscriptions/listen`; SSE resumability (`Last-Event-ID`) is gone, so a broken response stream loses the in-flight request and the client re-issues it [60]. Server-initiated requests (sampling, elicitation, roots) are replaced by the multi-round-trip `input_required` pattern and Roots/Sampling/Logging are deprecated [60]. Which clients negotiate it: Claude Code's v2 runtime (v2.1.232+ with feature flags, default from v2.1.274 on third-party providers/gateways) asks HTTP servers for 2026-07-28 only when `MCP_PROTOCOL_NEGOTIATION=auto`; the Claude Code docs say connectors and stdio servers stay on the legacy handshake unless that variable is set, and the 2025-11-25 servers remain reachable through the spec's backward-compatibility rules [6][61]. No other client fetched (claude.ai connectors, ChatGPT developer mode, Codex, Gemini CLI, Antigravity, Cursor, xAI API) documents 2026-07-28 support, and the Messages API MCP connector still links the 2025-11-25 authorization spec [64] — so the front door must keep serving the handshake-based revisions; whether FastMCP 4.0.x (MCP Python SDK v2 base) already answers `server/discover` and the new headers was not confirmed on the fetched FastMCP pages (unverified as of 2026-09-24).

**Claude (claude.ai / Desktop / Cowork / mobile).** Add at Settings → Connectors → "Add custom connector" with the remote URL; "Optionally, click 'Advanced settings' to specify an OAuth Client ID and OAuth Client Secret"; servers must be "reachable over the public internet from Anthropic's IP ranges" [1]. Outbound MCP calls originate from `160.79.104.0/21` [18]. Only Owners add connectors on Team/Enterprise; individuals add their own on Free/Pro/Max; Free is limited to one [1]. Tools can be disabled per conversation from the "Search and tools" menu; Anthropic advises "Disable any tools that can take write actions" when using Research [1]. Mobile: web connectors work on iOS/Android; installing custom connectors on mobile is beta ("Claude Desktop and web remain the primary path") [2]. Registered connectors then flow automatically into Claude Code (`/mcp` to view), cloud sessions and routines when the active credential is a claude.ai login — not when `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper`, `CLAUDE_CODE_OAUTH_TOKEN`, an `ANTHROPIC_PROFILE`/federation credential, or a third-party provider (Bedrock / Agent Platform / Foundry) is active [6][8].

**claude.ai Artifacts as a status-dashboard front door.** An artifact published from Claude Code (Pro/Max/Team/Enterprise, v2.1.209+ for connector calls) "can call MCP connectors each time someone views it, so the page shows current data rather than a snapshot"; Claude declares which connectors the page may call at publish time, only connectors from the claude.ai account qualify (local `.mcp.json` servers can feed the build but not the published page), the page fetches on load and can refresh on an interval or a button, and calls run through the *viewer's* connection after a one-time permission ask [65]. This reuses the same custom-connector registration: once `https://mcp.<domain>/mcp` is a claude.ai connector, a prompt like "build a status board artifact that pulls `list_jobs` and `server_health` through my assistant connector when the page loads" yields a live dashboard at `claude.ai/code/artifact/…` that also works in the Claude mobile app. Constraints: a connector-backed artifact cannot be shared to a public link on any plan (private-only on Pro/Max), and Claude Code v2.1.265+ refuses a publish whose declared tool names match none the connector exposes [65]. Routines republishing an artifact that holds a connector grant will ask for approval rather than run silently [8].

**Claude Projects and Claude Tag.** A Project (public beta on Pro/Max, rolling out; not on Team/Enterprise yet) is "one ongoing conversation where Claude coordinates a stream of related work", starting a cloud-session thread per task, sharing repositories, project instructions (≤16,000 chars) and project memory across threads, steerable from the mobile app; threads get "the connectors on your claude.ai account" but nothing from the local Claude Code setup [66]. As a control surface for this server it is a coordinator on top of cloud sessions, so the same connector rule applies (custom connector or committed `.mcp.json`). **Claude Tag** — the organization-managed `@Claude` in Slack running in an ephemeral sandbox with admin-scoped connections and usage-balance billing — "is available on Team and Enterprise plans … It isn't available on individual plans (Free, Pro, or Max)" [67]; on Max the Pro/Max Claude-in-Slack path in the table above is the one that exists.

**Claude Code CLI.** `claude mcp add --transport http <name> <url> --header "Authorization: Bearer …"`; scopes `local | project (.mcp.json) | user`; OAuth via `/mcp` or `claude mcp login <name>` (v2.1.186+); `headersHelper` script for dynamic headers; per-server `timeout` (ms, min 1000); default tool-output cap 25,000 tokens (`MAX_MCP_OUTPUT_TOKENS`, per-tool `_meta.anthropic/maxResultSizeChars`); long calls auto-background after 2 min (`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`); idle timeout 5 min for HTTP [6]. Tool search is on by default (Claude 4.5-generation models and later; off with a custom `ANTHROPIC_BASE_URL` or `ENABLE_TOOL_SEARCH=false`) so large tool lists don't bloat context; v2.1.232 is instead the version from which Claude Code uses the v2 MCP client runtime (MCP TypeScript SDK 2.0, adds protocol revision 2026-07-28) in sessions that fetch feature flags, and from v2.1.274 the v2 runtime is the default on Bedrock/Agent Platform/Foundry, gateway sessions and sessions with feature-flag fetching disabled; `MCP_SDK_GENERATION=v1|v2` forces a runtime and `MCP_PROTOCOL_NEGOTIATION=auto|legacy` controls whether Claude Code asks servers for 2026-07-28 (`auto`) or stays on the handshake revisions (`legacy`, the default for stdio servers and connectors) [6].

**Claude Code Channels (research preview).** "A channel is an MCP server that pushes events into your running Claude Code session"; Telegram, Discord, iMessage plugins ship in `claude-plugins-official`; requires Bun; start with `claude --channels plugin:telegram@claude-plugins-official`; pair with `/telegram:access pair <code>` then `/telegram:access policy allowlist` [3]. A custom channel is a stdio MCP server declaring `capabilities.experimental['claude/channel']` and emitting `notifications/claude/channel`; the reference shows a 30-line Bun webhook receiver on port 8788 and a `reply` tool for two-way chat; permission prompts can be relayed to the channel (`claude/channel/permission`) [4]. Custom channels need `--dangerously-load-development-channels` during the preview [4]. Available on Pro/Max and with Anthropic Console API-key authentication (permitted by default); admin-enabled on Team/Enterprise via `channelsEnabled`; not on Bedrock, Google Cloud's Agent Platform (Vertex) or Foundry [3][16]. Operational prerequisites for a launchd-driven channel session on the Mac Mini: the iMessage plugin reads `~/Library/Messages/chat.db`, so macOS must grant **Full Disk Access** to whichever app launched Bun (Terminal, iTerm, or — under launchd — the process's responsible app; without it the server exits with `authorization denied`), and the first reply triggers a macOS **Automation** prompt allowing that terminal to control Messages [3]. When channels run in non-interactive `-p` mode, "tools that need terminal input, such as multiple-choice questions and plan mode approval, are disabled so the session never stalls waiting for input" [3]. On the v2 MCP runtime with `MCP_PROTOCOL_NEGOTIATION=auto`, a channel server that negotiates protocol revision 2026-07-28 is **not registered as a channel** (channels cannot carry messages on the new revision), so a custom webhook channel must stay on a 2025-xx revision [3][6].

**Claude Code Remote Control.** "Remote Control connects claude.ai/code or the Claude app for iOS and Android to a Claude Code session running on your machine"; requires Pro/Max/Team/Enterprise subscription login, "API keys are not supported"; modes: `claude remote-control` (server mode, multiple sessions), `claude --remote-control`, `/remote-control`; sessions reconnect after sleep and queue permission prompts; `/config` toggles "Push when Claude decides" and "Push when actions required"; resume window ~4 h after the server stops [5]. From the phone you can attach photos/files, approve tool calls, and use Manual/Accept-edits/Plan (not Bypass) [12].

**Claude Code cross-session messaging (v2.1.224+ on macOS/Linux).** Claude uses `ListAgents`/`SendMessage` (user-facing `/list-agents`, alias `/peers`) to find and message "your other Claude Code sessions on this machine, and reach your sessions on other machines or in the cloud"; same-machine delivery is over a per-session Unix socket (`CLAUDE_CODE_MESSAGING_SOCKET`, never through Anthropic), while cloud sessions and sessions on other machines appear in the listing only while *this* session is connected to Remote Control and travel through Anthropic servers, arriving over the target machine's Remote Control connection; starting (not just replying to) a cross-machine conversation needs v2.1.225+ [63]. This is a direct "phone/terminal → Mac Mini session" path complementary to channels: a Remote-Control-connected session on a laptop (or a cloud session steered from the phone) can message a named, Remote-Control-connected session on the Mac Mini (`claude remote-control --name ai-server`), and an `offline` target queues the message until it reconnects [63]. Safety model: the receiving Claude is told the message came from another session, it "can't approve anything", commands in the text never execute, and inbound handling follows `crossSessionInbound` (`accept`/`hold`/`refuse`) — by default a bypass-permissions receiver *holds* messages for approval, and a `-p` worker drops held messages after `dialogExpiry` (5 min) unless started with `crossSessionInbound: accept` in `--settings`; `isolatePeerMachines: true` forces approval before any message leaves the machine [63]. A launchd `claude -p` session binds an inbox socket and appears in listings (bare mode does not), so the Mac Mini channel session can also be a messaging target [63]. Not available with an API key or on Bedrock/Agent Platform/Foundry for the beyond-this-machine case [63].

**Claude Code cloud sessions + Routines.** Cloud sessions: Pro/Max/Team (+Enterprise premium seats), GitHub-backed, `claude --cloud "task"` and `claude -p "msg" --cloud <session-id>` to steer from any machine [7]. Routines: saved prompt + repos + connectors; triggers = schedule (min 1 h), **API** (`POST https://api.anthropic.com/v1/claude_code/routines/{trig_…}/fire`, `Authorization: Bearer sk-ant-oat01-…`, optional `text` ≤65,536 chars, returns `claude_code_session_url`), GitHub events; per-routine tokens, "no read access"; 30 fires/hour/routine, 100 API fires/hour/account; routines "run autonomously … without stopping for approval apart from some artifact actions" (publishing a new artifact still asks; republishing an existing one is silent only when it is unshared, page-only and carries no connector grant) [8][9]. Fire text arrives wrapped as untrusted `<routine-fire-payload>` [8], whereas since v2.1.213 the routine's *saved prompt* is received "as its assigned task" rather than as an untrusted background notification [8]. `/schedule` can add GitHub triggers from the CLI (v2.1.225+) but API triggers/tokens are web-only; one-off runs don't count against the daily run cap [8]. The `/fire` reference lists `anthropic-version: 2023-06-01` as required and the `anthropic-beta: experimental-cc-routine-2026-04-01` header as optional (accepted with or without it) [9].

**Claude Desktop scheduled tasks and Dispatch.** Local scheduled tasks (Desktop ≥1.1.5368) fire every ≥1 min while the app is open, with per-task permission mode and always-allow memory [11]. They "only run while the desktop app is running and your computer is awake. If your computer sleeps through a scheduled time, the run is skipped"; the **Keep computer awake** toggle (Settings → Desktop app → General) prevents idle-sleep (a closed laptop lid still sleeps — moot on a headless Mac Mini, but the toggle is still the documented way to stop idle-sleep from skipping runs), and each run is staggered by a deterministic few-minute offset [11]. Missed-run semantics: on app start or wake, Desktop looks back seven days and "starts exactly one catch-up run for the most recently missed time and discards anything older", so a daily task that missed six days runs once; write prompts with a time guard if timing matters [11]. Tasks can't send or receive desktop cross-session messages, and MCP tools marked `requiresUserInteraction` stall every run [11]. Dispatch: "message Claude from your phone and have it work on your desktop computer"; limited beta on Pro/Max; uses configured connectors; push when done or needs approval; requires the desktop app open and awake [13][14].

**ChatGPT.** Developer mode (Settings → Security and login → Developer mode) gives "full Model Context Protocol (MCP) client support for all tools, both read and write"; "SSE and streaming HTTP" transports; auth "OAuth, No Authentication, and Mixed"; write actions "by default require confirmation" [21]. Servers are added at chatgpt.com/plugins ("Enter the MCP server URL, including the `/mcp` path", or choose **Tunnel** — the "Secure MCP Tunnel" lets you "connect a private MCP server in developer mode without exposing the server to the public internet" via a `tunnel_id`; tunnels "do not replace the public HTTPS endpoint required for plugin submission") [24]. Personal plugins live in "your personal plugins" directory and can be used without submission; public directory listing needs identity verification, privacy/terms URLs, tool annotations (`readOnlyHint`, `openWorldHint`, `destructiveHint`) and 5 positive + 3 negative test cases [25][26]. OAuth details: PRM at `/.well-known/oauth-protected-resource`; CIMD preferred with `none` (PKCE public client) or `private_key_jwt`; DCR fallback; redirect URIs `https://chatgpt.com/connector/oauth/{callback_id}` or `https://chatgpt.com/connector_platform_oauth_redirect`; declaring both `noauth` and `oauth2` allows anonymous calls with optional linking [23]. Deep research/company knowledge require read-only `search` and `fetch` tools [22].

**Codex.** `[mcp_servers.x] url = "https://…/mcp"`, `bearer_token_env_var`, `http_headers`, `env_http_headers`; `codex mcp login <name>` with CIMD/DCR or `--oauth-client-id`; `default_tools_approval_mode = auto|prompt|writes|approve`, `enabled_tools`/`disabled_tools`, per-tool `output_token_limit`; config shared by CLI, desktop app and IDE extension [29].

**Gemini CLI / Antigravity.** Gemini CLI `mcpServers.<name>`: `httpUrl` (Streamable HTTP) or `url` (SSE), `headers`, `timeout` (default 600,000 ms), `trust`, `includeTools`/`excludeTools`; OAuth auto-discovered, tokens in `~/.gemini/mcp-oauth-tokens.json`; Google ADC and IAP service-account modes [30]. Antigravity: `~/.gemini/config/mcp_config.json` or `.agents/mcp_config.json`, `serverUrl` for SSE/HTTP/WebSocket, DCR OAuth or `clientId`/`clientSecret`, custom `headers`; tools run in **Ask** mode by default, policies like `mcp(server/*)` [31].

**xAI Grok.** API-side only: `{"type":"mcp","server_url":…,"server_label":…,"authorization":"<token>","allowed_tools":[…]}`; "Streaming HTTP and SSE transports are supported"; works with the native SDK, OpenAI-compatible Responses API and Speech-to-Speech; `require_approval`/`connector_id` unsupported [34].

**Cursor.** `mcp.json` `{"url": "https://…/mcp", "headers": {"Authorization": "Bearer …"}}` or `auth: {CLIENT_ID, CLIENT_SECRET, scopes}`; transports stdio/SSE/Streamable HTTP; enterprise allowlists and network sandbox modes [37].

**iOS Shortcuts.** No MCP. The realistic bridge is a shortcut that POSTs JSON to the server's HTTPS API with Cloudflare Access service-token headers, invoked from Siri, the Action button or an automation [39]; the `Use Model` action can pre-process text with the on-device/PCC/ChatGPT model before the call [38].

**Telegram/Slack.** Telegram Bot API: `sendMessage`/`sendDocument`; webhooks and `getUpdates` are mutually exclusive [57]; ≤1 msg/s per chat, ~30 msg/s bulk by default (up to 1,000 msg/s with the paid-broadcast feature at 0.1 Stars/message above the free 30/s — irrelevant at this server's ~1,500 msg/month), 20 msg/min per group, 50 MB send / 20 MB `getFile` [56]. Slack: `chat.postMessage` "one message per second per channel"; tiers 1–4 = 1+/20+/50+/100+ per minute per method per workspace [58].

## 3. Headless / server automation fit

- **Non-interactive tool exposure.** A FastMCP (v4.0.x, MCP Python SDK v2 base; latest v4.0.9 shown as "September 24" on the releases page with no year rendered, so the 2026 date is (unverified as of 2026-09-24)) [46] server run with `mcp.run(transport="http", host="127.0.0.1", port=8765)` serves `/mcp` [45]. Authentication choices: `JWTVerifier` (JWKS), `StaticTokenVerifier` (dev only: "should never be used in production"), `OAuthProxy` (GitHub/Google/Azure upstream presented as DCR-capable AS), `RemoteAuthProvider` (DCR IdPs), full `OAuthProvider` [42][43][44].
- **Exposure.** Existing Cloudflare Tunnel: `cloudflared tunnel create mcp`, ingress `mcp.<domain> → http://localhost:8765` (or via Caddy), `cloudflared tunnel route dns` [53]. Cloudflare Access can front the hostname as an MCP-aware app: Zero Trust → Access controls → AI controls → MCP servers → add `https://mcp.<domain>/mcp`, attach policies/IdP, optional "Apply instant authentication" so users go straight to the IdP [48]. **MCP server portals** aggregate up to 80 servers on one `/mcp` URL, can hide individual tools/prompts (`default_disabled`, aliases), connect stdio-only clients through `npx mcp-remote@latest <portal>/mcp`, and accept **service tokens** for machine callers (`CF-Access-Client-Id` / `CF-Access-Client-Secret`) [49][51]. Logpush export of portal logs is Enterprise-only; Gateway routing of portal traffic carries no stated plan restriction, and portals otherwise have no plan gate stated [49]. Access lists a free plan "Best for teams under 50 users" and $7/user/month pay-as-you-go [52].
- **SaaS-managed vs customer-managed MCP servers (Cloudflare's split, and why it decides the OAuth design).** Cloudflare distinguishes a **customer-managed** MCP server — "the MCP server runs on a hostname you control in Cloudflare, but the server code … already handles its own OAuth flow": you add it under AI controls → MCP servers, Access policies gate the hostname, and the server's own OAuth AS stays in charge — from a **SaaS-managed** one, where you create an *Access for SaaS* (OIDC) application, hand its OAuth endpoints/credentials to the MCP server, and "the MCP server implements the OAuth authorization code flow against Cloudflare Access and receives an `access_token`"; users "will be prompted to log in to your identity provider and are only granted access if they pass your Access policies", and the origin sees the Access JWT as `Cf-Access-Jwt-Assertion` (re-forwardable downstream as `Cf-Access-Token`) [48]. Consequence for claude.ai's connector OAuth: Access *alone* does not act as an MCP-spec authorization server (no PRM at `/.well-known/oauth-protected-resource`, no CIMD/DCR endpoint on the MCP hostname is documented), so a bare Access-fronted FastMCP endpoint satisfies claude.ai/ChatGPT only through the **MCP-servers app + "instant authentication"** browser-redirect path, where the client's OAuth attempt is intercepted by Access [48]; if that path fails for a given client (see the FastMCP/claude.ai issue list in §5), the fallback is FastMCP's own `OAuthProxy`/`RemoteAuthProvider` with Access for SaaS as the upstream IdP (the SaaS-managed shape), or a no-auth endpoint reachable only via service tokens for CLI clients. Which of the two shapes claude.ai's connector flow completes end-to-end against this server was not exercised in this session (unverified as of 2026-09-24).
- **Headless callers into the vendors' clouds.** Only Anthropic offers a documented, subscription-billed HTTP trigger from the server into the vendor's agent (routine `/fire`, no SDK, per-routine token, 429 with `Retry-After`) [9]. The other Anthropic-side headless path is the **Messages API MCP connector** (`mcp_servers: [{type: "url", url, name, authorization_token}]` plus an MCPToolset in `tools`, beta header `mcp-client-2025-11-20` or `mcp-client-2026-09-15` for pinned tool lists; tool calls only, server must be public HTTP/SSE) — it lets a plain API call drive this server's tools with no MCP client of its own, but it is metered Claude Platform usage authenticated with an `x-api-key`, which this server's no-API-key / subscription-only policy rejects outright, so it is named here only to close the option [64]. ChatGPT's dev-mode connection is browser-driven; Codex/Cursor/Gemini CLI are local processes you drive yourself.
- **Rate limits that matter for a status/launch front door.** Claude Code MCP: 25k-token output cap, 5-min idle, auto-background at 2 min [6]. Routines: 30/h/routine, 100/h/account, min schedule 1 h, daily run cap shown at claude.ai/code/routines [8][9]. Cloud sessions share the account's subscription limits ("no separate compute charge") [7]. Telegram ~30 msg/s bulk, 1/s/chat [56]; Slack 1/s/channel [58]. ChatGPT/Codex/Gemini publish no MCP-call rate limits (Not found — searched: developer-mode, plugins auth/security, Gemini CLI MCP page).
- **Terms on personal-server automation.** Anthropic: routines and Remote Control are subscription features; API keys explicitly not supported for Remote Control, so the "no API key" policy is not merely allowed but required [5][16]. OpenAI: developer mode is a first-party feature on paid plans and personal plugins need no submission [21][25]; the matrix records ChatGPT-plan scripting via Codex as "Grey/Yes*" [59]. Perplexity consumer terms ban automation per the matrix [59]. Gemini: consumer login lane disputed [59].
- **Security posture (vendor guidance).** Anthropic: "Only connect to trusted servers", "Be aware of prompt injections: Malicious MCP servers may include hidden instructions", review tool approvals, disable write tools in Research [1]. OpenAI: "Assume prompt injection and malicious inputs will reach your server. Check every input and keep audit logs"; "Use the host's confirmation prompts for destructive actions"; "avoid storing any sensitive information from ChatGPT users"; annotate tools with `readOnlyHint`/`destructiveHint` [22][26][27]. Channels: sender allowlist is the only gate and "Anyone who can reply through the channel can approve or deny tool use in your session" [3]. Routines: fire text is wrapped as untrusted; prompt must opt in [8]. Spec: audience-bound tokens, no passthrough, HTTPS-only AS endpoints, exact redirect-URI matching [40].

## 5. Strengths & weaknesses per reviews

Attribution: only primary docs and GitHub issue trackers were reachable; no HN/Reddit/X pass ("Not found — searched: web-search budget exhausted; community.openai.com search fetch returned an empty page").

- **Claude Remote Control / channels (GitHub issues, anthropics/claude-code).** Same-day regression report #96793 (2026-09-24, filed on v2.1.281, regression introduced in v2.1.280, last-good v2.1.279 or earlier, Linux/Remote-SSH): "Remote Control sessions killed by mid-session SIGSEGV … JSC idle-time GC (Bun 1.4.3, VS Code Remote-SSH / Linux)" — pin the Mac Mini CLI below v2.1.280 until it is fixed (macOS reproduction not shown in the issue, so treat as precautionary) [62]; #96818: bypass mode "still prompts for computer use, Run In Terminal and over Remote Control"; #96817: computer-use prompts "can't be answered over Remote Control"; #94620 (2026-09-16; a general Claude Code feature request, not Remote-Control-specific): no built-in cross-platform way to list running sessions and their state [20] — note `/list-agents` (cross-session messaging, v2.1.224+) now lists live sessions on this machine plus cloud/Remote-Control sessions, which partly answers it [63]. Reading: the surface is genuinely useful (phone steering + push) but ships fast and breaks; pin the CLI version on the Mac Mini as the matrix already recommends ("Claude Code shipped 10 releases in 10 days … pin every binary") [59].
- **FastMCP ↔ claude.ai/ChatGPT OAuth (GitHub issues, jlowin/fastmcp).** Long-lived #972 "OAuth works with MCP Inspector but not with Claude Integrations" (2025-06 → still updated 2026-09-18); #3949 "GitHubProvider returns 400 when claude.ai skips Dynamic Client Registration" (2026-04); #3720 "CIMD fetch fails when metadata URL returns 302 redirect (e.g. Cloudflare)" (2026-03); #4265 refresh-token rotation without grace window forces re-auth (2026-06 → 2026-09) [47]. Reading: hand-rolled OAuth in front of a personal server is where the time goes; letting Cloudflare Access be the authorization server, or using a `no-auth` endpoint reachable only via Access service tokens, avoids the whole class.
- **ChatGPT developer mode.** OpenAI's own copy calls it "powerful but dangerous" and warns about "model mistakes on write actions that could destroy data, and malicious MCPs" [21]; the Secure MCP Tunnel is new and its runtime instructions were not on the fetched page [24]. Community sentiment: not found (see above).
- **Reliability record (matrix, vendor status pages Aug 1–Sep 24, 2026).** Anthropic 37 incidents, OpenAI 33 in the window [59]. Claude cloud-session VMs are reclaimed after inactivity, including while waiting for an MCP approval [7].
- **Design strengths.** Anthropic's connector registration is reused by seven surfaces (chat, Code CLI, cloud sessions, routines, Desktop/Dispatch, connector-backed Artifacts, Projects) [6][8][14][65][66]; Codex offers the finest per-tool approval policy (`writes`, `output_token_limit`) [29]; Gemini CLI's `includeTools` allowlist and Antigravity's `mcp(server/*)` policies are clean for read-only exposure [30][31].
- **Design weaknesses.** No vendor app receives server-initiated push over MCP; MCP "tasks" were experimental in 2025-11-25 and, in the current 2026-07-28 revision, were moved out of the core protocol into an official extension (`io.modelcontextprotocol/tasks`, polling via `tasks/get`); no client fetched advertises them [41][60]. Custom connectors on Claude mobile are beta [2]. Routines cannot schedule under 1 h and their API token must be minted in the web UI [8].

## 6. Finance / trading relevance

Specific to this category: **none of the front doors adds market data or order capability**; they are control planes. Relevant constraints: (a) keep Atlas tools read-only when exposed (ledger, thesis, paper-P&L, job status) and never expose an order tool — there is no live order path today and Anthropic/OpenAI both tell users to disable or confirm write tools [1][21]; (b) ChatGPT deep research can pull Atlas reports if the server exposes read-only `search`/`fetch` tools [22]; (c) the matrix notes Claude Max with training toggle off and the API-key lanes as data-handling-clean for theses, while consumer Perplexity/Gemini lanes are not [59] — so do not paste Atlas theses into Gemini/Perplexity apps to "query" them; call the server's own tools from Claude/ChatGPT instead; (d) Grok's API MCP tool would let a Grok call pull Atlas status, but that is metered API, contrary to the subscription preference [34].

## 7. Integration recipe for our server

**Recommended shape: one FastMCP "front door" behind the existing tunnel, Cloudflare Access as the identity layer, Telegram (already live) plus Claude Code channels for push.**

1. **Tool surface (read-mostly).** `list_jobs(status, limit)`, `get_job(job_id)` (status, cost, audit tail), `get_deliverable(job_id)` (markdown or dashboard URL), `server_health()`, plus exactly one mutating tool `enqueue_job(skill, payload)` flagged with `annotations={"readOnlyHint": False, "destructiveHint": False}` and gated by an allowlist of skills. Read tools carry `readOnlyHint: True` so ChatGPT/Claude/Codex treat them as safe [26][29].

```python
# src/gateway/mcp_front_door.py  (FastMCP 4.x; run under launchd on 127.0.0.1:8765)
import os, jwt, httpx
from fastmcp import FastMCP
from fastmcp.server.auth.providers.jwt import JWTVerifier

TEAM = os.environ["CF_ACCESS_TEAM"]           # e.g. "piserchia"
AUD  = os.environ["CF_ACCESS_AUD"]            # Access application audience tag
auth = JWTVerifier(                            # validates the Access-issued JWT
    jwks_uri=f"https://{TEAM}.cloudflareaccess.com/cdn-cgi/access/certs",
    issuer=f"https://{TEAM}.cloudflareaccess.com",
    audience=AUD,
)
mcp = FastMCP(name="assistant-server", auth=auth)

@mcp.tool(annotations={"readOnlyHint": True})
def list_jobs(status: str = "running", limit: int = 20) -> list[dict]:
    """Recent jobs with status, skill, started_at, cost_usd."""
    return db.jobs(status=status, limit=limit)

@mcp.tool(annotations={"readOnlyHint": True})
def get_deliverable(job_id: str) -> str:
    """Markdown deliverable or dashboard URL for a finished job."""
    return db.deliverable(job_id)

@mcp.tool(annotations={"readOnlyHint": False, "destructiveHint": False})
def enqueue_job(skill: str, payload: str = "") -> dict:
    """Queue a job; only skills in ENQUEUE_ALLOWLIST are accepted."""
    if skill not in ENQUEUE_ALLOWLIST: raise ValueError("skill not allowed")
    return queue.enqueue(skill, payload, source="mcp")

if __name__ == "__main__":
    mcp.run(transport="http", host="127.0.0.1", port=8765)   # serves /mcp
```
(`mcp.run(transport="http", …)` and the `/mcp` default path per [45]; `JWTVerifier(jwks_uri, issuer, audience)` per [42][44]. Cloudflare's MCP-server guide states the origin receives the Access JWT in the `Cf-Access-Jwt-Assertion` header (which the MCP server may re-forward downstream as `Cf-Access-Token`); it documents no `Authorization: Bearer` copy to the origin, so validate `Cf-Access-Jwt-Assertion` in middleware rather than relying on `JWTVerifier` reading the Authorization header — i.e. in practice run FastMCP with `auth=None` and add a Starlette middleware that verifies `Cf-Access-Jwt-Assertion` against the same JWKS/issuer/audience shown above [48][50]. See the SaaS-managed vs customer-managed distinction in §3.)

2. **Expose.** Caddy already terminates the tunnel; add `mcp.<domain>` → `127.0.0.1:8765`. Cloudflare: proxied DNS record; Zero Trust → Access controls → AI controls → MCP servers → add `https://mcp.<domain>/mcp`; policy = owner's email via the existing IdP; optionally "Apply instant authentication" [48]. Register it as a **customer-managed** server (FastMCP keeps whatever auth it has; Access gates the hostname); switch to the SaaS-managed shape (Access for SaaS app as OAuth IdP behind FastMCP `OAuthProxy`) only if claude.ai/ChatGPT cannot complete the connector OAuth through Access alone [48]. Add a second policy with action **Service Auth** for a service token used by headless clients [51]. Optional: create an MCP portal so a single URL fronts this server plus Alpaca/EDGAR servers later, hiding `enqueue_job` from the portal if desired (`default_disabled`) [49].

3. **Register in each app.**
   - **claude.ai** (once; reused by Code CLI, cloud sessions, routines, Dispatch): Settings → Connectors → Add custom connector → `https://mcp.<domain>/mcp`; complete the Access login; in Research, untick `enqueue_job` [1][6][8].
   - **claude.ai Artifacts dashboard** (same registration): from any Claude Code session ≥v2.1.209, "build a status-board artifact that pulls `list_jobs`, `server_health` and the latest `get_deliverable` through my assistant connector when the page loads, refresh every 60 s, with a fallback message naming the connector"; keep it private (connector-backed pages cannot be shared publicly) and open it from the Claude mobile app [65].
   - **Claude Projects** (Pro/Max beta, if rolled out): threads inherit claude.ai connectors, so the same connector serves a project that coordinates several server-ops cloud sessions from one conversation [66].
   - **Claude Code on any machine** (service token, no browser): `claude mcp add --transport http assistant https://mcp.<domain>/mcp --scope user --header "CF-Access-Client-Id: $CF_ID" --header "CF-Access-Client-Secret: $CF_SECRET"` [6][51].
   - **ChatGPT** (Plus+): Settings → Security and login → Developer mode; chatgpt.com/plugins → + → URL `https://mcp.<domain>/mcp` (OAuth through Access/DCR) or **Tunnel** (`tunnel_id`) if the public endpoint is undesirable [21][24]. Expect write-confirmation prompts on `enqueue_job` [21].
   - **Codex**: `[mcp_servers.assistant] url = "https://mcp.<domain>/mcp"` + `http_headers = { "CF-Access-Client-Id" = "…" }` and `env_http_headers = { "CF-Access-Client-Secret" = "CF_SECRET" }`; `default_tools_approval_mode = "writes"` [29].
   - **Gemini CLI / Antigravity**: `"assistant": {"httpUrl": "https://mcp.<domain>/mcp", "headers": {…}, "includeTools": ["list_jobs","get_job","get_deliverable","server_health"]}` [30]; Antigravity `serverUrl` + `headers` [31].
   - **Cursor**: `.cursor/mcp.json` `{"assistant": {"url": "https://mcp.<domain>/mcp", "headers": {…}}}` [37].
   - **iOS Shortcuts**: "Get Contents of URL" POST `https://api.<domain>/jobs` with the two `CF-Access-*` headers and a JSON body; trigger via Siri/Action button [39][51]. (Not MCP; hits the existing REST gateway.)

4. **Push paths (deliverables reach the owner).**
   - Keep the Telegram bot as the universal completion notifier (`sendDocument` ≤50 MB) [56].
   - Run a persistent Claude Code session on the Mac Mini under launchd with `claude --channels plugin:telegram@claude-plugins-official` (or iMessage, which needs no bot and no token) so "ask from the phone, work on the box" works; lock with `/telegram:access policy allowlist` [3]. For unattended operation use `--permission-mode acceptEdits` plus allow-rules rather than `--dangerously-skip-permissions` [3].
   - Optional: a 30-line webhook channel (`notifications/claude/channel`) so the job runner can POST completions *into* that session for triage [4].
   - For phone steering with native push, start `claude remote-control --name "ai-server"` in the server repo and enable both push toggles in `/config`; or open a Remote Control session ad hoc [5][12].
   - With that named Remote Control session up, any other Remote-Control-connected session (laptop terminal, or a cloud session driven from the phone) can `/list-agents` and message `ai-server` directly (cross-session messaging, v2.1.224+; v2.1.225+ to start the conversation); give the Mac Mini session `crossSessionInbound: "accept"` in `--settings` if it runs `-p`, or leave the default so messages from bypass-mode senders are held for approval [63].
   - Routines: create a "server-ops" routine with an API trigger; the job runner can `curl -X POST …/fire -H "Authorization: Bearer $ROUTINE_TOKEN" -H "anthropic-version: 2023-06-01" -d '{"text": "…"}'` to spawn a cloud investigation whose session URL is posted to Telegram [9]. Mind 30/h/routine and 100/h/account, and that the routine's prompt must reference the `routine-fire-payload` [8][9].

**Gotchas.**
- Anthropic's connector fetch comes from `160.79.104.0/21` [18]; Access policies are identity-based, so no IP allowlist is needed, but a WAF rule can additionally restrict `mcp.<domain>` to that range plus Cloudflare's own edges.
- Claude Code servers added with `claude mcp add` are *not* visible to routines; only claude.ai connectors (or a committed `.mcp.json`) are [8].
- Connectors don't load when `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper`, `CLAUDE_CODE_OAUTH_TOKEN`, an `ANTHROPIC_PROFILE`/federation credential or a third-party provider is active [6] — consistent with the no-API-key policy; keep the Mac Mini sessions on subscription login.
- MCP output cap 25k tokens in Claude Code [6]: return job summaries and links, never raw logs.
- FastMCP `StaticTokenVerifier` is dev-only [44]; don't use it for the public hostname.
- Cloudflare service-token secrets issued from 2026-08-26 use a `cfast_[40 alnum][8 checksum]` format; older 64-hex secrets stay valid without rotation — cosmetic for the recipe, but don't write a regex that assumes hex [51].
- Team/Enterprise-only controls that do **not** apply on Max, listed so the reader stops looking for them: a managed `managed-mcp.json` allowlist/denylist (`allowedMcpServers`/`deniedMcpServers`; when present on a cloud-session host it drops all claude.ai connectors) and **Trusted Devices** (beta; requires device enrollment via `/login` and re-auth after 18 h before Remote Control can be viewed or steered) [5][6].
- Custom connectors on Claude mobile are beta; register from web/desktop, then use from mobile [2].
- Channels/Remote Control/routines are research-preview or "experimental" surfaces with dated beta headers and same-week regressions [8][9][20]; pin CLI versions and smoke-test on bump.
- Cloudflare returns 302 on some metadata paths, which broke FastMCP CIMD fetches (#3720) [47]; letting Access be the AS sidesteps it.
- ChatGPT: dev mode is web-only in the docs; the public-directory route requires identity verification and a privacy policy — unnecessary for a personal plugin [24][26].
- Cloud sessions and routines cannot reach `mcp.<domain>` directly unless the environment's network allowlist includes it; connector traffic "reaches their services through Anthropic's servers" so connectors need no allowlist change [8].

## 8. Verdict

1. Anthropic is the only vendor where one connector registration serves chat (web/desktop/mobile-beta), Claude Code, cloud sessions, routines, Dispatch, live Artifacts dashboards and Projects, all on the Max plan already paid for [1][6][8][14][65][66].
2. ChatGPT developer mode is the best second door (full read/write MCP on Plus, optional Secure MCP Tunnel), but web-only and pull-only [21][24].
3. Gemini, Grok and Perplexity consumer apps have no documented custom-MCP client; their CLIs/APIs (Gemini CLI, Antigravity, xAI API) do, with header or OAuth auth [30][31][34][36].
4. Real push still comes only from Telegram/iMessage/Slack and Claude mobile notifications via Remote Control/Dispatch/channels; MCP is pull [3][5][14][56].
5. Do it with Cloudflare Access as the OAuth/identity layer plus service tokens for CLIs, a read-mostly FastMCP tool set, and Telegram + Claude Code channels for deliverables.

Fit scores (1–10): **research n/a** (front-door plumbing does no research); **coding/agentic 8** (Remote Control + channels + routine `/fire` make the server reachable from phone, terminal and cloud); **cost efficiency 9** ($0 marginal on existing Max, Cloudflare free tier; only ChatGPT Plus is an optional add); **automation friendliness 7** (service tokens, routine API and channels are headless; but connectors need a one-time browser OAuth, routines cap 1 h/30 fires, and channels/Remote Control are preview-grade); **trading research 4** (useful only as a read-only status/thesis console for Atlas; adds no data or execution and must never expose an order tool).
