**Goal:** Every job is observable and every launch is notified: tokens and a typed terminal reason land in Postgres on both lanes (turns and cost on the Anthropic lane); every human launch (Telegram **and web**) DMs on completion or failure and every scheduled failure DMs within 60 s through a durable outbox that survives bot restarts; the real monthly cost is known at both windows; the server has an off-site backup that includes the atlas database and restores; and the sessions burned monthly on the un-provisioned swing vertical stop.

**Architecture:** Additive only. One migration (**008**, not the P0 plan's "007" — that number is taken by the slice's `007_provider_columns.py`) adds nullable columns on `jobs`/`tasks` and the `notifications` outbox; `jobs.status` and its CHECK (006) are untouched. A new package `src/notify/` owns outbox rows and the Telegram renderer; the runner **always** writes the row and keeps the legacy `tasks:notify`/`jobs:done` publishes byte-identical; **only the bot reads `NOTIFY_OUTBOX`** and picks the renderer. A pure `src/runner/result_capture.py` reads the full SDK `ResultMessage` on the **Anthropic path only** (the Codex path already has `ExecResult`) and derives the typed `terminal_reason`; a capture-free `usage_columns()` maps either lane's usage dict to the token columns; `src/runner/pricing.py` is the single definition of `cost_usd_list`. Ops hygiene is shell + launchd; the provisioning pre-check is a fail-open guard in `_tick_schedules`.

**Tech Stack:** Python 3.12, SQLAlchemy 2 async + Alembic, Redis (`fakeredis` in tests), python-telegram-bot, httpx, `claude-agent-sdk>=0.1.81,<0.2` (bundled CLI 2.1.139), pytest (`asyncio_mode=auto`), bash under launchd. Baseline: **2140 tests collected** at `b47ebf9`, lint `All clean!`.
