# Observability, control and the trading unblock — design spec (2026-10-05)

> **Status: PROPOSED — awaiting owner review.** Nothing here is implemented. It **supersedes `docs/superpowers/specs/2026-09-25-multi-model-platform-design.md`** (frozen 2026-09-27 after three applied adversarial review rounds) and narrows it to the project that spec's own reviewers and the owner agreed is defensible. Every mechanism kept below carries the citation that spec gave it; where it marked something unverified, the marking is kept. `docs/superpowers/plans/2026-09-25-multi-model-platform-p0.md` remains the executable form of Phase 1, minus the one task named in §10.

## 0) What this is, and what it is not

**The owner's ask, verbatim intent:** make the server observable, then fix the trading verticals that have been dead on a missing token since August — and cut existing spend while doing it.

**Three reasons the old spec was cut rather than phased.**

1. **It was too large to be correct.** 1,143 lines of spec and an 11,404-line Phase-0 plan against an 11,100-line `src/` tree. Its review rounds found 8 criticals, then 6, then 18 — a *rising* curve. A document that gets more wrong the longer it is reviewed is not nearly done; it is oversized. **This spec is what was made small; the Phase-0 plan was re-pointed, not re-cut** — it still stands at ≈10,700 lines for Phase 1's 20 tasks, long by design (verbatim code and tests per step) and a known debt the size argument above does not claim to have paid.
2. **Its own D0 fork admitted the headline ask was undeliverable under the owner's money rules.** Under the standing 2026-08-17 decisions (Codex on ChatGPT Free, unpaid Gemini key, **no metered spend**) the other vendors could only grade, critique and classify until an owner-gated late phase: the first non-Anthropic *writer* was a ≥20-job canary in P4, the red-window hedge landed at P5 for exactly one task class, and `code-project` never hedged the window in either branch because every canary job still consumed an Anthropic gate session (old §0c). The owner has now chosen that branch: **keep the money rules, delete the cross-vendor machinery from scope** rather than phase it.
3. **The fleet already runs at ~100 % of its weekly window.** The prod ledger shows ≈ **$960/month list-equivalent** at the 1-h cache-write rate the subscription actually uses, against a fixed weekly allowance bracketed at **≈ $207–275/week** (old §2.8). Adding belts competes with work the owner already wants. Cutting existing spend pays before adding capability.

**Not in scope, said plainly: running work on other models.** No Codex executor, no Gemini/Cerebras/Groq/OpenRouter lane, no cross-vendor grader, no executor seam, no provider ladder. Anthropic is the only executor and the only reviewer. Every deleted item appears once in **§14** with the trigger that would reopen it and a pointer into the superseded spec; nothing else below re-litigates deleted scope.

### 2.2 Control plane (`src/control/`, new)

- `grammar.py` — one parser, replacing three divergent ones (Telegram leading-flags-only `telegram_bot.py:140-172`, `web.py`'s `CreateJobRequest`, `mcp_dispatch.py:35-40`). `/task <text> [--kind] [--model] [--effort] [--project] [--timeout] [--watch] [--quiet]` keeps today's flags, with **unknown models refused at parse time** (today `telegram_bot.py:157` passes them through unchecked). The registry ships in Phase 4, so Phase 2's interim source of truth is `_MODEL_ALIASES`' **value** set, with a test asserting an unknown id is refused; Phase 4 re-points the same check at `registry/models.py` without changing the parser's contract. `help [<verb>]` is a grammar verb rendered from the same verb/flag table the parser uses, not a literal block (`telegram_bot.py:1297`), and a test asserts `help` lists exactly the live verbs.
- `intents.py` — pure `(actor, args) → Result | Error` over the models; `enqueue_job` (`jobs.py:16`) stays the only mutation path into the runner. `cancel` gains a durable path for queued jobs (`LREM` + status flip; today `main.py:1368-1404` reaches running jobs only). Every human launch creates a `Task` + origin, not only Telegram (`telegram_bot.py:231-256` vs `web.py:399-405`).
- `policy.py` — the god/privilege strip and `kind=god` rejection written **once** (INV-18, C10), imported by Telegram, web, CLI and `mcp_dispatch`.
- `views.py` + `renderers/{telegram,sse,cli}.py` — one view object per card, rendered per channel; the renderers are the only code that knows Telegram's 4096 chars, 64-byte callbacks and ≤8 buttons (C23) and MarkdownV2 escaping (fixes `TROUBLESHOOTING.md:699-707`).

### 2.4 Event / audit model

All 33 existing kinds and shapes are kept (C14). Added, appended to the per-job JSONL and mirrored to `jobs:stream:<id>`: `executor_started{cli_version, lane, queue_wait_ms}`, `quota_snapshot{window, used_pct, resets_at, source}`, `heartbeat{turn, last_tool, tokens_so_far, elapsed_s}` every 15 s, `job_held{reason, next_check}`, `provider_refused{reason, auth_key, observed_only}`, `contract_resolved{checks, on_fail}`, `evidence_check{check, pass, detail, timeout?}`, `dod_tick{pass_count, total}`, `deliverable_registered{kind, title, ref}`, `done_verdict{verdict, missing[]}`, `merge_gate_verdict{reviewer, verdict, findings_n}`, `approval_requested/decided`, `notice_queued/sent/failed`, `subagent_result{agent, text}` (the **full** `Task` tool_result text — today's 500-char `result_preview`, `session.py:1182`, drops everything after the first paragraph), `lane_budget{lane, family, used, budget}`. `terminal_reason` is stamped on `job_completed`/`job_failed`. The JSONL stays the durable trace and the task state-machine input (`main.py:1053-1266`); rows are derived from it, never the reverse, so `reconcile.py` ("last terminal wins") is unchanged.

**Typed terminal reasons** replace the banner regex (`session.py:495-534`, kept one release as a belt): `ok | max_turns | interrupted | timeout | api_error{status} | rate_limited | auth_expired | unrecognized_model | account_on_hold | oauth_revoked | billing_error | provider_refused{reason} | error` — 13 values, exactly the `TERMINAL_REASONS` tuple Phase 1 builds. `provider_refused{reason}` is a policy refusal (the §6 settings-override refusal, or `DeployRefused`) and is **never escalated**; `error` is the catch-all for an unmapped exception. The name `provider_refused` is kept from the superseded spec although this scope has one provider, so the tuple and the audit kind do not fork. The last three are mapped from the vendor's own error *category*, not an HTTP status: `system/api_retry` carries `error ∈ {rate_limit, overloaded, account_on_hold, oauth_org_not_allowed, billing_error}` (`docs/research/llm-landscape-2026-09/claude-anthropic.md`, hereafter `claude-anthropic.md`, line 51; `docs/research/llm-landscape-2026-09/crosscut-subscription-automation-tos.md`, hereafter `crosscut-tos`, line 71), the `StopFailure` hook matchers are the same set (`crosscut-tos` line 213), and `crosscut-tos` line 457 item 1(c) says to parse those events and "back off the whole scheduler, not the job" — `autoContinueAtUsageLimit` is "not offered at all" for `-p` runs. Runtime: `account_on_hold`/`oauth_revoked` **hold every lane except `owner`**, queue `notice(kind=provider_enforcement, severity=high)` and DM an ApprovalCard; `billing_error` is the **first** `possible_credit_overflow` trigger (§2.5). `unrecognized_model` is the silent-empty-success rejection — assert `model_usage ∋ requested model ∧ duration_api_ms > 0`, because the pinned bundled CLI 2.1.139 may return a silent empty success for an unknown id (`claude-anthropic.md §7`).

**Clone lifetime and post-step order.** Today `sync_canonical` + `cleanup_workspace` run inside `run_session`'s `finally` (`session.py:1035-1045`) before `_finish_job` publishes `jobs:done` (`main.py:1299`), so nothing that must see the clone — evidence checks, `tests_green` — can run. They move into `finalize_workspace(job, ws)`, invoked from a `finally` wrapping `_process_job`'s try/except, **never as a success-chain step**: the `QuotaExhausted` arm (`main.py:446-458`), the `SkillResolutionError` arm, the timeout arm and the generic arm all return without running the chain, and removal is unconditional today only because it sits in `run_session`'s own `finally`. Order, with the status flip ahead of everything that reads it: `run_session` returns → `contracts.check` + deliverable auto-detection (clone alive) → gate verdict capture → `_finish_job` (status, result, `jobs:done`) → refetch → `promote_deferred_for` (it decides from `j.status == completed`, `plans.py:197`) → `_maybe_review` (`main.py:388-390`) → writeback → learning → task lifecycle → notify → `jobs:reviewed`. Every post-step runs under `asyncio.wait_for(_POST_STEP_TIMEOUT_SECONDS)` and the whole chain under a 900 s wall clock: today `wait_for` wraps only `run_session` (`main.py:376-380`) while `_run_with_held_slot` releases the semaphore only after every post-step returns (`main.py:188-194`), so a hung `tests_green` or post-review holds one of two prod slots and the clone indefinitely. A timeout stamps `evidence_check{name, timeout: true}` + `done_verdict=unverified` and never wedges the slot. ff-sync semantics (INV-16) are unchanged; only the clone's lifetime extends past `run_session`.

### 2.5 Cost and quota ledger

**`cost_usd_list` has exactly one definition: the runner's own computation from tokens, in `src/runner/pricing.py`**, with cache writes priced from `usage.cache_creation.ephemeral_{1h,5m}_input_tokens` at the matching rate. The subscription's cache TTL is 1 h (`claude-anthropic.md` line 220) and prod records 100 % of cache writes as 1-h (45.3 M 1-h, 0 5-m over 634 priced jobs), i.e. $10/M Opus and $6/M Sonnet, not the 5-m rate. The SDK's `total_cost_usd` lands in `jobs.sdk_cost_usd` and is **not** assumed to be the same figure; the Phase-1 exit criterion is that the two agree within 1 %, or the divergence is recorded together with the rate the CLI uses. Neither is ever a bill: cards read `$0 marginal · $3.49 list-equiv`.

**Window source.** `RateLimitEvent` → `quota_snapshots(source=vendor)` for every one of the SDK's five `rate_limit_type` literals — `{five_hour, seven_day, seven_day_opus, seven_day_sonnet, overage}` (`claude_agent_sdk/types.py:1181-1183`, pinned 0.1.81) — recorded verbatim, with `family` **taken from the event type, never inferred** (`seven_day_opus` ⇒ `opus`, `seven_day_sonnet` ⇒ `sonnet`, `seven_day` ⇒ `all`), plus `status`/`resets_at`, `utilization` when present, and `overage_status`/`overage_resets_at`/`overage_disabled_reason` (`types.py:1202-1209`); today `quota.py:31-48` reads only `status` and `resets_at`. Prod to 2026-09-27 10:32Z: **732 events = 702 `five_hour` (698 `allowed`, 4 `allowed_warning` at 0.91–0.96, 2 `rejected`) + 28 `seven_day` `allowed_warning`, utilization 0.25 → 0.58, every one carrying `resets_at` 2026-10-02T00:00Z** — so the weekly window is **fixed**, not rolling. `source=vendor-statusline` is the newest line of `volumes/telemetry/claude_rate_limits.jsonl`, appended by the owner's *own* interactive sessions' `statusLine` command (one-time setup, D8; the owner already runs four resident `claude` TUIs on the Mini — state map §2.8 — and the window is shared across every Keychain consumer, so the owner's gauge *is* the runner's gauge). `source=inferred` applies only *between* readings, from rolling `call_ledger` `cost_usd_list` sums per model family, and is labelled "inferred" on every surface — "uncalibrated" only when the newest reading is older than 7 d. **No figure is ever shown as vendor-sourced unless a vendor event or the status-line file carried it, and no runner-driven probe session exists.**

**The weekly allowance, calibrated in dollars** because that is the unit the budgets use: vendor readings 0.25 (≈ $69 of `cost_usd_list` consumed since the window opened) → 0.58 (≈ $120) bracket it at **≈ $207–275/week** (≈ 176–235 M tokens at the current mix); the marginal pair implies ≈ $155. **Take $200/week as the working denominator and re-derive it weekly from the series** — the reconcile script prints it. At the Sep 23–25 rate of 88.3 M tokens/day the window fills in **≈ 2.5–3 days**.

**Calibration anchor — prod ledger, trailing 30 d** (634 priced completed jobs since 2026-08-26; this supersedes `crosscut-finance-trading-ai.md §3`'s "empirical calibration", which read the *dev checkout's* 16-JSONL sample and is ~60× low — do not re-cite it): 749 M cache-read + 45.3 M cache-write (all 1-h) + 9.35 M output + 20 k uncached input. Priced at list at the 1-h rate: **≈ $960/month-equivalent** — opus-5 $414, opus-4-7 $255, sonnet-4-6 $151, opus-4-8 $143. Shape: **8–10× the Max 5x seat** (MISSION §K line 136: $100) and **cache-*write*-led in dollars** (write ≈ 42 %, read ≈ 37 %, output ≈ 22 %) although 93 % cache-read in tokens. Honest caveat: on `crosscut-tos §4.3`'s own formula (no cache-creation term) the same ledger is ≈ $550/month ≈ 5.5× the seat; ≈ $960 is the more complete accounting but not the metric that section's "~2× the plan price" heuristic was written against. Medians: opus-5 ≈ $3.43 (n = 109), fleet ≈ $0.59. Trailing 7 d is the anchor that matters: daily tokens 09-12..22 were 6.7–32.7 M (mean ≈ 23 M), then **09-23 = 98.7 M, 09-24 = 68.0 M** — the alpha flywheel (commit 5448c81, 2026-09-23) tripled daily consumption two days before the old spec was written. Measured alpha load is **47–86 M/day (mean ≈ 51 M ≈ +1,550 M/month)**. Per-model job counts are deliberately not restated: one consistent set comes from a single `scripts/cost-reconcile.py --days 30` run, with unattributable jobs reported as `unpriced` and their tokens shown rather than dropped.

**Lane weekly budgets** in `cost_usd_list` per model family, read from `Settings` (`LANE_WEEKLY_BUDGET_JSON`), **sized trailing-7-d × 1.2** from the reconcile script's printed table — pasted in by hand once at Phase-3 entry and from then **re-cut weekly by a `cost-reconcile` schedule row** (read-only SQL on a cron, no LLM call, Phase 1) which writes the new values into `Settings` itself, so the weekly cadence the budget model depends on has a mechanism and an owner and never falls back to the stale 30-d mean — enforced in the job loop as `job_held{reason=lane_budget_exhausted, next_check}` on rolling 7-d `call_ledger` sums, surfaced on the QuotaStrip with an 80 % warning. The owner lane is never held; **governed atlas and alpha rows are never auto-held** — a governed lane at 100 % raises a LOOP.md §7 proposal plus an owner notice. Cost-weighting per family is a **modelling assumption, not a vendor statement**: the research establishes only that separate Opus/Sonnet weekly bars exist (`crosscut-tos` line 63) and that token budgets are unpublished (`claude-anthropic.md` line 90). The first `seven_day_opus`/`seven_day_sonnet` event the SDK emits settles it; if the bar is time- or token-weighted the dollar budgets over-hold Opus lanes and under-hold Sonnet ones.

**Metered-spend tripwires.** The only path to metered Anthropic spend is usage credits (`claude-anthropic.md §3`: credits continue past caps at API rates and the cache TTL drops to 5 m), which would replace the `rejected` event the pause logic keys on with a silent bill. D4 confirms credits $0, auto-reload off, spend limit $0. Runtime, **vendor signal first**: `terminal_reason=billing_error`, then `overage_status == allowed` while `status == rejected`, then any `rate_limit_type=overage` event, then the ledger heuristic (including any `cache_write_5m_tokens > 0` reading, since the TTL drop is itself the credits signature) — each queues `notice(kind=possible_credit_overflow, severity=high)` and holds non-owner, non-governed lanes until the owner acknowledges. The "ordinary usage" drift alarm is **alarm-only and keyed on a rate, not a count** (prod already carries 32 `allowed_warning`, so a count baseline would fire permanently and carry no signal): `notice(kind=ordinary_usage_exceeded)` when rolling-30-d `cost_usd_list` exceeds the Phase-1-measured baseline by 25 %, or `rejected` events exceed 2 per 30 d, or vendor `seven_day` utilization crosses 0.85 before day 5 of the window. `allowed_warning` is never a trigger, and no tripwire here is a plan-price hold. **`ANTHROPIC_CREDIT_MODE=1`** is the pre-decided response should the paused Agent-SDK credit split return without notice ($100/month at Max 5x is ~3–4 days at the measured rate): every lane budget re-sized to the pool, owner and kernel funded first, governed atlas rows via a pre-drafted LOOP.md §7 proposal.

Semantics the cards depend on: `approvals` lists open ids + kind + age (the only discovery path for `approve`, which the CLI and PWA otherwise cannot find); `jobs --blocked` = waiting on the owner, distinct from `--held` (window or budget); `retry` re-runs the same spec by default; `mute <job>` stops card edits, `mute today` silences non-failure cards until local midnight, `mute --lane=` silences a lane's; `lane hold` is the fleet-level lever short of `/clear` — durable `quota:lane:<lane>:hold_until`, already-popped jobs finish, newly due rows enqueue and park as `job_held{reason=owner_hold}`, and because a hold is not a schedule edit `governed` rows need no proposal; `job <id> --verdicts` renders the VerdictCard, the surface needed to actually *read* a review finding; `schedule list` paginates in the renderer (41 rows exceed 4096 chars; today `telegram_bot.py:547-552` prints them all in one message). Telegram: bare text = `task`; `/status`, `/tasks`, `/chat`, `/god`, `/resume`, `/projects` unchanged; `/clear` requires a confirm button; the three ghost commands (`/cancel <prefix>`, `/status <prefix>`, `/proposals`) become real and `/rate` leaves the help text (endpoint kept; 👍/👎 on DeliverableCards only).

**Cards** — every card is a `views.py` object and the phase model is single-sourced there, identical on every surface: `queued (lane · pos · est)` → `held` → `starting (model · clone 3 s)` → `working (elapsed/timeout · last tool · files · turn · tokens · DoD m/n)` → `blocked` → `done (verdicts pending)` → `reviewed` | `failed`.
- **JobCard** — one message per job, edited on phase change and otherwise coalesced to ≤1 edit/10 s. Edits are **silent**; DoneCard, FailedCard and ApprovalCard are *new* reply messages, which is what notifies. Buttons `[Cancel] [Details] [Mute]`, callback `j:<8-char>:c|d|m` (≤64 bytes); `[Open]` appears only once the PWA ships. The message id is persisted in `notifications.external_ref` so a bot restart loses nothing. **Eligibility:** `origin_channel ∈ {telegram, pwa, cli}` and schedule rows with `notify=always` get a card; `notify=failures` (the default for all 41 rows) gets only the FailedCard; `notify=never` is digest-only; dispatch/escalation children inherit the parent's eligibility; `watch <job>` subscribes any job and `mute` reverses it. With ~20 machine-launched jobs/day (state map §2.3: scheduler 79, dispatch-MCP 67, event-trigger 312 vs Telegram 55 in 7 d) this keeps the phone quiet while the digest carries the fleet.
- **DoneCard** — verdict lines (gate, post-review; "pending" at `jobs:done`, filled at `jobs:reviewed`; the card says "done · verdicts pending", never "completed & verified", before the belts finish), `done_verdict` with DoD ticks, deliverables with deep links, cost strip, `[Reopen] [👍] [👎] [Send file]`. **FailedCard** — error class, `terminal_reason`, escalation hop, `[Retry] [Details] [Mute today]`; fires for scheduled jobs too (silent today, state map §5.7). **ApprovalCard** — from an `approvals` row, `[Approve] [Reject] [Ask]`; a deploy parks here instead of failing. **VerdictCard** — per stage: reviewer, verdict, each finding's severity/location/text, from `job <id> --verdicts` and `GET /api/jobs/{id}/verdicts`.
- **DeliverableCard** — title, kind, 500-char preview, `[Send file]` (Telegram document ≤50 MB) as the **primary file path indefinitely**: a Telegram deep link opens in the in-app browser, which carries neither the paste-bootstrapped bearer nor an Access cookie and so hits `web.py:_check_auth`'s Basic prompt (`web.py:49-63`). **ScheduleCard** — next fire, last outcome, adherence flag (DARK/NEVER_RAN/STUCK/FAILURE_STREAK/LATE/MISSING), `[Run now] [Pause] [Edit]`. **QuotaStrip** — `5h ok · resets 14:10 · 7d 58 % (vendor, 40 min) · lane atlas opus 62 % of week · lane atlas HELD by owner until 08:00`; the "(inferred)" marker is mandatory whenever `source=inferred`. **CostCard** (Monday 08:00 + `/cost`) — by lane × skill top-5 with week-over-week delta, per-family budget bar, `purpose=build` tokens this week, drift-notice state, R2 bucket size. **AtlasCard** — per vertical: last run, status (ok/stale/blocked), last decision, gate status, provisioning gaps. **AlertHistory** (`/alerts`) — outbox rows with delivery status, newest first.
- **DailyDigest 07:15** replaces `schedule-monitor.sh`'s DM via `python -m src.notify digest` on the same launchd timer — the only phone surface for 41 rows under the `notify=failures` default, so it is defined rather than named: header (`date · 5h ok · 7d 58 % (vendor, 40 min)`), `ran: n ok / n failed / n held / n skipped(misfire)` with failed rows named by `terminal_reason`, adherence findings, deliverables produced, open approvals and blocked-job ages, next 6 fires, lane holds in force. **Quiet rule, preserving `schedule-monitor.sh:7-9, :17, :47-58`:** send only when there is a failure, finding, deliverable or open approval since the last digest; otherwise silent, except the Sunday all-clear; never more than one per 12 h unless a finding is new.

**What "watch progress" means.** `watch <job>` posts a JobCard and subscribes it to edits until terminal. The card moves because the `heartbeat{turn, last_tool, tokens_so_far, elapsed_s}` emitter ships in the same phase as the card — a 15 s task inside `_run_in_process`, and without it a 30-minute job shows a card that does not move, the opposite of the phase's promise. `DoD m/n` shows only the live-evaluable subset (`lifecycle_marker_present`, `file_exists`/`glob_matched`, `tests_ran`, `budget_within`); the post-session checks (`git_pushed`, `claimed_files_exist`, `tests_green`, `url_200`, `db_row`) tick at `finalize_workspace`. ### 4.1 The Deliverable Contract

Declared in frontmatter `done:`, overridable per job via `payload.contract`, resolved once at session start (`contract_resolved`), and **checked by the runner — never by a model**.

**Default contract — the single source for what `done_verdict` means.** A job with no `done:` block runs the class-aware default: a pass yields `done_verdict=unverified` (the runner observed nothing the skill promised), a fail yields `failed_checks`, and `verified` requires a declared contract. Class-aware so the signal is not drowned in noise (512 `task_complete` events against 646 `job_completed` — roughly one completed job in five has no marker): `chat`/`utility-*` → `budget_within`; everything else → `claimed_files_exist ∧ budget_within`, with `lifecycle_marker_present` added **only when the job has a `task_id`**, since the marker protocol is a task-lifecycle contract (`session.py:405-460`) and a blanket rule would grade every `_evaluate` run and every legitimate `TASK_QUESTION:` as `failed_checks`. `jobs.status` is untouched. **`on_fail` defaults to `flag`** fleet-wide (card + scoreboard); `fail` only for deploy-verify skills where the check *is* the deliverable; trading-ledger checks always flag, so a flaky probe cannot dark a loop. `fix_round` reuses the evaluator fix loop (`main.py:949-985`, max 2) when a skill opts in. `done:` blocks land on the 10 highest-volume skills first.

**Evidence bundle.** `<job>.evidence.json` from (a) check results, (b) auto-detected deliverables (Write/Edit targets under `projects/**`, `docs/**`, `research/**`; the ff-sync SHA; PR URLs in final text; `<job>.summary.md`), (c) an *optional* `<<<DELIVERABLES … DELIVERABLES>>>` block using the same parse path as `<<<TASK_PLAN>>>` (`session.py:405-460`; no mandatory `<<<EVIDENCE>>>` ceremony), (d) the workspace diff summary. `deliverables` rows are what the cards link.

## 5) Scheduling and lanes

**One scheduler of record** (`main.py:1314-1362`); no vendor-native scheduler is a producer. Fixes: **commit before RPUSH** (closes the race the retry ladder absorbs, `main.py:196-230`); `next_run_at = croniter.next(slot)`, slot-based rather than from completion; `misfire_policy ∈ {skip, catch_up_once}` so misfires stop being dropped silently; `notify ∈ {never, failures, always}`; `expects: {artifact, within}` per row flipping `LATE`/`MISSING` and DMing; `kind` validated at enqueue against `list_all()` minus `policy.py`'s forbidden set (`god`, `_*`-internal, `isolation: host` — C21), which retires `JobKind`. **Adherence** runs in-process every 30 min in addition to the 07:15 launchd belt, and findings surface in-band on ScheduleCards and the Schedules view.

**Lanes** keyed `owner | kernel | atlas | alpha | build | utility | background`, derived **from the resolved skill first and from `created_by` only as a fallback**: `division: alpha` → `alpha`; `division: atlas` → `atlas`; `_*`-internal → `utility`; `god`/owner-originated → `owner`; `server-patch`/`deploy-autopilot` under a phase label → `build`; then `created_by`: `telegram/web/cli → owner`, `deploy-autopilot/event-trigger/self-diagnose → kernel`, `writeback:`/`escalation*`/`evaluator:`/`eval-fix:`/`auto-continue:`/`plan:`/`learning:`/`dispatch-mcp` → the parent job's lane else `utility`, everything else → `background` (the untouched `jobs:queue`). A `created_by`-only rule mis-routes the largest consumer: `alpha-governor` arrives as `created_by="event-trigger:idle-queue"` (`events.py:427`) and its `alpha-research` stage jobs as `created_by="dispatch-mcp"` (`mcp_dispatch.py:120,134`), so ≈58 % of week 39's load would have had no lane and no budget while an alpha exhaustion held the `kernel` ops lane carrying deploy-autopilot, self-diagnose and the breaker. The PR prints the complete prefix → lane table from `grep -rn 'created_by=' src/` (20 producers today) with a named default, and `test_lanes` asserts every prefix maps to a declared lane.

Job loop: `promote_held()` → `sem.acquire()` → `BLPOP` over `ALL_QUEUE_KEYS` minus lanes under an in-process backoff, with a strict `jobs:queue:owner`-only pop when a non-owner job count has filled the reservation. `owner` first, `kernel` second, **and the remaining keys rotate each iteration** — `BLPOP k1 k2 …` returns from the first non-empty key, so a fixed order is a strict priority queue, not fairness, and the atlas lane is self-feeding and ≈60–75 % of the fleet, so a standing backlog would starve the lanes carrying the task-lifecycle children (`writeback`, `evaluator`, `eval-fix`, `auto-continue`) that advance owner tasks. A held job is **parked per lane** in `jobs:held:<lane>` with its slot released — never `LPUSH`ed back (it would be re-popped ahead of other lanes) and never slept on while holding a slot (that would halve the runner at prod `MAX_CONCURRENT_JOBS=2`); INV-12's "requeue at the front" survives because the promoter re-inserts at the lane head. The loop **always drains every lane key**, so `LANES_ENABLED=0` changes only where `enqueue_job` pushes and is safe in both directions. `job_held{reason}` is audited on the first hold and on a reason change only (~600 events per 5-h red window otherwise) and queues `notice(kind=lane_held|window_red, severity=high)`, debounced one per lane per reason per window. **The complete value set is `job_held{reason ∈ window_red | lane_budget_exhausted | owner_hold | provider_enforcement | possible_credit_overflow}`** — the `owner` lane is exempt from all five, and `governed` atlas and alpha rows are exempt from the three this spec adds (`lane_budget_exhausted` §2.5, `provider_enforcement` §2.4, `possible_credit_overflow` §2.5), which raise a LOOP.md §7 proposal plus an owner notice instead; a governed row is held only by the pre-existing vendor window gate (`window_red`) or an explicit `owner_hold`, which is what §9's guarantee means — without it a red window is invisible to the 41 `notify=failures` rows until the next digest, which is exactly the governor-dark pattern. `OWNER_RESERVED_SLOTS=1`, soft at concurrency 2 (the owner job is *next*, never behind a second atlas job).

**The nine sites that address `jobs:queue` by name** all move to `db.queue_key(lane)`/`ALL_QUEUE_KEYS`: `reconcile.py:88-101` (otherwise every lane-queued row looks stranded at startup and is re-`RPUSH`ed on every restart; `requeue_stranded_queued` must also treat `ZRANGE jobs:held:<lane>` members as present, or a held row is re-queued with a spurious audit every restart), `telegram_bot.py:512` (`/clear` must delete every lane list **and** every held ZSET, flipping those rows to failed — otherwise a `/clear` during a red window refills the queue from the ZSETs, since held rows keep `status=queued`), `web.py:335` (`/health` depth = sum over lanes **plus a separate `held` count under a new stable JSON key**, per C23 — a lane sum alone reports 0 while jobs sit held, and that number is what the heartbeat Worker and `healthcheck-all.sh` consume), `main.py:347` (tail requeue), `main.py:449` (INV-12 `LPUSH` → lane head), `plans.py:181/233/311` (owner plan DAG children derive the lane from the parent task's origin, or the most common owner flow lands in `background`), `healthcheck-all.sh:244`, `db.py:11`.

**Schedules as data.** `scripts/seed-schedules.sh` stays the sole writer for non-owner-edited rows, with one immediate fix: `server-deploy` runs it on **every** deploy and its `ON CONFLICT (name) DO UPDATE SET cron_expression = …` (`seed-schedules.sh:40-46`; `server-deploy/SKILL.md:149`) would silently revert every phone edit, so the clause becomes per-column — `cron_expression = CASE WHEN schedules.owner_edited THEN schedules.cron_expression ELSE EXCLUDED.cron_expression END`, and the same for `job_payload` — because `ON CONFLICT … DO UPDATE … WHERE` is all-or-nothing for the whole `SET`. `owner_edited=true` rows keep cron and payload across deploys **only when `governed=false`**; atlas and alpha loop rows are `governed=true`, and a phone edit on them files a proposal for the **LOOP.md §7 front door** instead of writing the row. Phase 4 replaces the 41× `pipenv run python | psql` loop with `schedules.yml` + a validating Python seeder (cron collisions, DST-anchored ET pairs) **as a drop-in behind the same path**: `seed-schedules.sh` becomes a two-line shim that execs `python -m src.schedules.seed`, so `server-deploy/SKILL.md:149` (protected) needs no edit and the old shell seeder cannot keep running against rows the Python seeder owns. Row shape: `{name, cron (tz America/New_York, DST pairs generated by the seeder), kind, payload, lane, misfire_policy, notify, governed, expects: {artifact, within}}`.

**Phone add**: `/schedule add "weekdays 17:30 America/New_York" --kind=… --project=…` → a deterministic preset parser (`weekdays HH:MM [TZ]`, `daily HH:MM`, `every <dow> HH:MM`, `hourly`, `every N hours`, raw 5-field cron; an unparsed phrase answers "use a preset or cron") → a confirm button showing the cron and the next three fires. Through Phase 2, `add` accepts a raw 5-field cron only. There is no free-text-to-cron model call in this spec.

**Credential canary as a schedule**: a daily `claude -p ping` with the `model_usage` assertion, **through the runner's own path** — `scripts/credential-canary.sh` on a launchd timer invoking the SDK-bundled CLI from the runner venv, never the brew binary, because a brew-CLI pass says nothing about the runner's path.
